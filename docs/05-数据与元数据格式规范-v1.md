# 数据与元数据格式规范 v1

本文档描述本版本读写的两种文件：数据库文件 `X.cdb` 与元数据文件 `X.cdb.meta.json`。

---

## 1. `X.cdb` 数据库文件

### 1.1 文本约定

| 项 | 规则 | 原因 |
| --- | --- | --- |
| 编码 | UTF-8，**无 BOM** | 与原版一致，避免首字节差异 |
| 换行 | `LF`（`\n`） | 跨平台稳定，git diff 干净 |
| 缩进 | **1 个 Tab** | 与原版一致 |
| 尾随换行 | **没有** | 与原版一致 |
| 键顺序 | **保持读入顺序** | 保证「打开→保存」字节不变 |
| 数字 | 保留原始文本；新建数字用规范格式（整数值无小数点，`R` 格式，小写 `e`） | 避免 `1` 变成 `1.0` |

> 校验方式：把 `TestData1.cdb`(266,859 B) 与 `TestData2.cdb`(62,004 B) 打开后原样保存，
> 两个文件的字节与 SHA-256 完全不变（见《测试与验收报告》§4）。

### 1.2 顶层结构

```jsonc
{
	"sheets": [ /* 表对象数组 */ ],
	"customTypes": [ /* 自定义类型数组 */ ],
	"compress": false
}
```

键顺序固定为 `sheets, customTypes, compress`（读入顺序优先）。

### 1.3 表对象

```jsonc
{
	"name": "EventCard",
	"columns": [ /* 列对象数组，顺序即显示顺序 */ ],
	"lines": [ /* 行对象数组 */ ],
	"separators": [ 0, 33 ],          // 可选，整数数组
	"props": { /* 可选，表属性 */ }
}
```

- `lines` 中每个对象是「列名 → 值」的映射，**键顺序保留**。
- 保存时 `lines` 数组按内存中的行列表**整体重建**：行的增、删、移动都以界面为准；
  没有改动过的文件重建后字节不变（往返测试覆盖）。
- `separators` 的三种历史写法都能读：
  - `[0, 33]`（整数，**本版本写出的形式**）
  - `[{ "index": 0 }, ...]`
  - `[{ "id": "vocational" }, ...]`（按首列 ID 定位，读入后转为索引）
- 表没有分隔线时**不写** `separators` 键，避免无意义 diff。
- `props` 在表没有任何属性时**不写出**。

#### `props` 支持的键

| 键 | 类型 | 含义 |
| --- | --- | --- |
| `displayColumn` | string | 引用下拉显示用列名 |
| `displayIcon` | string | 引用下拉图标列名 |
| `hide` | bool | 隐藏子表（不出现在表列表） |
| `isProps` | bool | Properties 子表标记 |
| `hasIndex` | bool | 保存时为每行生成 `index` |
| `hasGroup` | bool | 保存时为每行生成 `group` |
| `dataFiles` | string | 外部数据文件 |
| `separatorTitles` | array | 与 `separators` 平行的标题数组 |

`hasIndex` / `hasGroup` 是**运行时虚拟字段**：开启后由写入器为每行补 `index` / `group`，
不占用真实列名。两者都**不在编辑界面里显示为列**，也不参与单元格编辑。

#### `index` / `group` 的生成规则

写入器在**每次保存前**重算这两个字段（`DerivedFields`），因此它们永远与当前行序一致，
不会因为手工改 JSON 而漂移。规则与 CastleDB 1.5 的 `save()` 完全一致：

- `hasIndex` 为真：`lines[i].index = i`（0 起）。
- `hasGroup` 为真：`group` 从 0 开始，**每遇到一条带标题的分隔线就 +1**；
  位于第 0 行之前的带标题分隔线算作第 0 组的开始，不再额外 +1。
- `hasGroup` 为真但**所有分隔线都没有标题**（即 `separatorTitles` 不存在）时，
  **不写** `group` —— 没有标题就没有可描述的组结构，这与 1.5 一致。
- 关闭开关时由命令删除这些字段，撤销时原样恢复。

`separatorTitles` 与 `separators` 等长且平行；**无标题的分隔线写成 `null`**（不是 `""`），
这样「没有标题」和「标题是空串」可以区分。

示例：

```jsonc
"separators": [0, 2, 4],
"props": { "hasIndex": true, "hasGroup": true, "separatorTitles": ["Head", null, "Tail"] }
```

生成结果：

| 行 | index | group | 说明 |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 前面的 "Head" 分隔线开启第 0 组 |
| 1 | 1 | 0 | |
| 2 | 2 | 0 | 前面的分隔线无标题，不开新组 |
| 3 | 3 | 0 | |
| 4 | 4 | 1 | 前面的 "Tail" 分隔线开启第 1 组 |

### 1.4 列对象

```jsonc
{
	"name": "rarity",
	"typeStr": "5:Common,Rare,Epic",
	"opt": true,            // 可选：允许该行缺此键
	"display": 1,           // 可选：显示格式
	"structRef": "Items@x", // 可选：与另一列共享定义
	"defaultValue": 0,      // 可选：新行默认值
	"kind": "localizable",  // 可选
	"scope": 1,             // 可选
	"documentation": "…",   // 可选
	"shared": true,         // 可选
	"enumStr": true         // 可选：Enum 存字符串而非索引
}
```

- `typeStr` 是类型编码，格式见 §1.5。`structRef` 存在时列**没有** `typeStr`。
- `opt`、`display`、`kind`、`scope`、`shared`、`enumStr` 为 `false` 时**不写出**该键。
- `display` 目前只用到 `1`（百分比显示），普通数值列不写该键；它只影响显示，不改变存储的值。
- `defaultValue` 存的是**该列类型的一个值**，因此可以是标量（`0`、`true`、`"text"`），
  也可以是容器（List 的数组、Properties 的对象），后两者按紧凑 JSON 写在一行里。
  它只在**插入新行**时使用，修改它不会回溯改写已有行。

### 1.5 `typeStr` 编码

| 值 | 类型 | 值形态 |
| --- | --- | --- |
| `"0"` | Id | string |
| `"1"` | Text | string |
| `"2"` | Bool | bool |
| `"3"` | Int | number |
| `"4"` | Float | number |
| `"5:A,B,C"` | Enum | number（索引）或 string（`enumStr`） |
| `"6:Sheet"` | Ref | string（目标表 ID） |
| `"7"` | Image | string（**相对路径**） |
| `"8"` | List | array of object |
| `"9:TypeName"` | Custom | 依类型而定 |
| `"10:A,B,C"` | Flags | number（位掩码） |
| `"11"` | Color | number（0xRRGGBB） |
| `"13"` | File | string（相对路径） |
| `"16"` | Dynamic | 任意 |
| `"17"` | Properties | object |
| `"18"` | Gradient | object |
| `"19"` | Curve | object |
| `"20"` | Guid | string（13 字符） |
| `"21"` | Polymorph | object |
| `"22"` | Formula | string |

> `"7"` Image 存的是路径本身，文件不会被复制、改名或转成 `.img`（需求 Q5）。编辑器
> 为了显示缩略图，会按 **`.cdb` 所在目录**解析相对路径去读原文件；读不到时只在界面
> 上标记，不写回任何内容。该列同时可以作为表的 `props.displayIcon` 图标列（C06）。

**不支持**：`"12"` Layer、`"14"` TilePos、`"15"` TileLayer —— 按需求 R1 移除地图功能，
遇到时抛出明确错误：

```
Map-related column type "Layer" (type 12) is not supported in this version.
```

### 1.6 Guid 编码

13 字符，`XXXX-XXXX-XXX`（第 4、9 位后是连字符），与 `cdb.Types.Guid.ofInt` 兼容。

## 2. `X.cdb.meta.json` 元数据文件

### 2.1 定位

- 与数据库**同目录同名**，追加 `.meta.json`：`Game.cdb` → `Game.cdb.meta.json`。
- **存显示状态**：列宽、行/列/单元格背景色、表与列的稳定 ID、窗口状态。
- 从 `metaVersion` 2 起还存**表格模板**（§2.5）：模板是「一组列定义」，本身不写进 `.cdb`，
  因为游戏端读的是数据，模板只是编辑器用来把几张表的列对齐的约定。
- 从 `metaVersion` 3 起还存**公共枚举 / 标志类型**（§2.6）：一个命名取值列表，多个列可以
  跟随它。取值仍然写进每一列的 `typeStr`，side-car 只记定义与绑定关系。
- 任何显示状态改动都立即写盘，**不会**让 `.cdb` 变脏。
- `.cdb` 文件里永远不会出现 `width`、背景色等字段。

### 2.2 结构

```jsonc
{
	"metaVersion": 3,
	"fileId": "9f2c…",                    // 元数据自身的 UUID
	"createdWith": "PalaceDB.CSharp/1.0",
	"tables": {
		"EventCard": {
			"tableId": "4a1b…",            // 表的稳定 ID（改名不变）
			"template": "tpl_5b1e9c02",    // 可选：这张表跟着哪个模板走
			"columns": {
				"5c7d…": { "name": "Title", "width": 180 },
				"7a10…": { "name": "rarity", "publicType": "Rarity" },
				"9b22…": { "name": "num", "autoIncrement": true }
			},
			"rowStyles":    { "vocational": { "bg": "#ffcc00" } },
			"columnStyles": { "5c7d…":      { "bg": "#e0e0ff" } },
			"cellStyles":   { "vocational": { "5c7d…": { "bg": "#ff0000" } } }
		}
	},
	"templates": {
		"tpl_5b1e9c02": { "name": "Event", "columns": [ /* 见 2.5 */ ] }
	},
	"publicTypes": {
		"Rarity": { "kind": "enum", "values": ["Common", "Rare", "Epic"] }
	},
	"windowState": { "width": 1200, "height": 800, "x": 120, "y": 80, "maximized": false },
	"appearance": { "scheme": "mint" }        // 可选：这份文件用哪套配色
}
```

- `columns` / `columnStyles` 的键是**列 ID（UUID）**，不是列名；`name` 是列名快照，
  用于外部改名后的回退匹配。
- `rowStyles` / `cellStyles` 的行键是**该行 ID 列的值**；表没有 ID 列时用行号字符串。
- 颜色统一写 `#rrggbb`（小写）。
- `appearance.scheme`：这份文件用的配色 id（与 `themes.css` 里的 `data-scheme` 一致）。
  整个 `appearance` 对象缺失表示从没为这个文件选过配色，打开时沿用本机偏好；
  写 `null` / 删掉字段都会回到这个状态。只写「和默认不同」的东西，所以没改过配色的
  文件不会因此多出一行。
- `windowState`：`width` / `height` 单位是设备无关像素（DIP），`x` / `y` 是窗口左上角
  在**虚拟桌面**坐标系里的位置（多显示器时可以为负）。`x` / `y` 缺失表示这个文件
  从未记录过位置，打开时保持默认摆放而不是跳到 (0,0)。`maximized` 为真时
  `width` / `height` 记的是**还原尺寸**（`RestoreBounds`），不是最大化后的尺寸。

#### 2.2.1 窗口几何的落屏规则（F17）

读到 `windowState` 后不能直接套用——显示器可能已经拔掉、分辨率可能变小。规则如下
（`WindowPlacement.Fit`，纯几何运算，与窗口系统无关）：

| 步骤 | 规则 |
| --- | --- |
| 尺寸兜底 | `width`/`height` 为 0、负数、NaN、无穷大时用默认值 1280×800 |
| 尺寸夹紧 | 不小于 640×400，不大于当前虚拟桌面尺寸 |
| 无位置 | `x`/`y` 缺失 → 在虚拟桌面居中 |
| 可见性判定 | 与虚拟桌面的交集在两个方向上都 ≥ 120px → 保留原位置 |
| 可见性不足 | 交集任一边 < 120px（窗口在屏幕外）→ 重新居中，而不是贴边 |
| 边缘微调 | 交集够大时，把左上角夹到「至少露出 120px」的范围内 |

写回时 `Capture` 把坐标四舍五入到整数（`.5` 向远离零取整），并保证尺寸不小于最小值。

### 2.3 同步算法（`SyncWith`）

打开文件时按 4 轮把元数据重新挂到当前结构上：

1. **按列名匹配** —— 正常路径，也是应用内改名后的路径。
2. **按位置回退** —— 处理在外部改名过的列。
3. **为新增列创建条目** —— 生成新 `columnId`。
4. **清理孤儿条目** —— 列已被删除的元数据丢弃。

### 2.4 容错

| 情况 | 行为 |
| --- | --- |
| 文件不存在 | 视为空元数据，正常打开 |
| JSON 损坏 | 改名为 `X.cdb.meta.json.bad`，重建空元数据，给出警告，**数据不受影响** |
| `metaVersion` 高于本版本 | 以只读方式打开文档，不覆盖元数据 |
| 文档只读 | 不写元数据 |

版本历史：

| `metaVersion` | 变化 |
| --- | --- |
| 1 | 列宽、颜色、稳定 ID、窗口状态、配色 |
| 2 | 增加 `tables.*.template` 与 `templates`（表格模板）。旧版本读到 2 会以只读方式打开，而不是把模板块丢掉 |
| 3 | 增加 `publicTypes`（公共枚举 / 标志类型）与列的 `publicType`、`autoIncrement`。旧版本读到 3 会以只读方式打开，而不是丢掉这些字段 |

### 2.5 表格模板

```jsonc
"templates": {
	"tpl_5b1e9c02": {
		"name": "Event",
		"columns": [
			{
				"name": "Title", "typeStr": "1",
				"opt": false, "display": "Normal", "kind": "None",
				"defaultValue": null, "enumStr": null, "scope": null,
				"documentation": null, "shared": false,
				"fields": []                        // List / Properties 的字段
			}
		]
	}
}
```

- 模板 id 形如 `tpl_` + 8 位十六进制；`tables.<表名>.template` 指向它，缺省表示不跟任何模板。
- `columns` 是**列定义的完整快照**（与 §1.4 的列对象同义，但脱离任何一张表独立存在），
  所以模板可以描述一张还不存在的表的列。
- 模板定义是**派生态**：编辑器在每次列改动后，用「刚被编辑的那张成员表」重写它；
  所有成员表一致时也用它对齐。因此不需要手工维护，撤销列改动时它跟着回到旧值。
- 打开文件时，指向不存在的模板的 `template` 字段会被清掉（`SyncWith`），
  不会因为模板被删掉就让表打不开。

## 3. 写盘安全

### 3.1 原子写入

所有 `.cdb` 与 `.meta.json` 的写入都走：

```
写临时文件（同目录） → File.Replace(临时, 目标, 备份) → 删除临时
```

保证任何时刻磁盘上的目标文件要么是旧内容、要么是新内容，**不会出现半截文件**。

### 3.2 自动备份

- 文件名：`X.cdb.autobackup`（同目录）。
- 内容：完整的 CDB 文本（与保存时写出的内容格式一致，含 `index`/`group` 等派生字段）。
- 触发：文档有未保存修改时，每 5 分钟一次（`PALACEDB_BACKUP_SECONDS` 可覆盖间隔，
  仅供自动化测试使用）。
- 数量：**只保留 1 个**（需求 Q1）。
- 清除：保存成功后删除；正常关闭时按用户选择删除（保存或明确放弃）。

**恢复判定**（`BackupRecovery.Inspect`）：

| 条件 | 状态 | 打开时的行为 |
| --- | --- | --- |
| 无备份文件 | `None` | 正常打开 |
| 备份 mtime ≤ 主文件 mtime | `Stale` | 静默删除备份，正常打开 |
| 备份 mtime > 主文件 mtime | `Newer` | 询问是否恢复 |

恢复流程（`BackupRecovery.Recover`）：

1. 读取备份文本；
2. **先用 `CdbReader.ParseDatabase` 校验**，不合法直接抛 `CdbFormatException`，主文件不动；
3. 校验通过后原子写入主文件；
4. 删除备份。

这条「先校验后覆盖」的顺序保证损坏的备份永远不会覆盖掉完好的数据库。

### 3.3 外部修改检测

`DatabaseDocument` 在打开、保存、另存为、以及「忽略一次外部改动」时记录文件的
`LastWriteTimeUtc`（`TouchStamp`）。宿主每 2 秒比较一次（`HasChangedOnDisk`），
不一致即视为外部改动：

- 无未保存修改 → 重新加载；
- 有未保存修改 → 询问用户（保留本地则刷新时间戳，不再重复提示）；
- 文件已不存在 → 不算改动，下次保存会重新创建。

### 3.4 只读判定顺序

1. 元数据要求只读 → 只读；
2. 文件带 `ReadOnly` 属性 → 只读；
3. 本进程另一个窗口已持有写槽（`OpenFileRegistry`）→ 只读，原因
   `it is already open in another window`；
4. 否则可写，并登记写槽（`Dispose` / 关闭窗口时释放）。

## 4. 剪贴板格式

复制/剪切写入系统剪贴板的纯文本是 JSON：

```jsonc
{
	"format": "palacedb/cells",
	"sheet": "EventCard",
	"includeIdColumn": false,
	"columns": ["Title", "Des"],
	"rows": [
		{ "cells": [ { "v": "职业培训", "t": "str" }, { "v": "…", "t": "str" } ] }
	]
}
```

- `v` 是**原始 JSON 值**（number / string / bool / array / object），保证类型不丢。
- `includeIdColumn` 为 `false` 时粘贴不会覆盖目标行的 ID 列。

## 5. 应用设置文件 `settings.json`

### 5.1 定位

与具体数据库无关的应用级偏好，存放在用户目录：

```
%LOCALAPPDATA%\PalaceDB\settings.json
```

环境变量 `PALACEDB_DATA_DIR` 可以把这个目录整体重定向（自动化测试用它把设置与
WebView2 缓存放到临时目录，避免污染真实用户配置）。同一目录下还有 `palacedb.log`
与 WebView2 的 profile 目录。

### 5.2 结构

```json
{
  "recentFiles": [
    "D://Work//Game//Data//Items.cdb",
    "D://Work//Game//Data//Enemies.cdb"
  ]
}
```

- `recentFiles`：最近打开过的数据库，**最新的在最前**，最多 10 条。
- 路径一律写**绝对路径**；重复项按大小写不敏感比较去重，重开同一文件只把它挪到最前。
- 文件缺失、损坏或为空时，程序用空列表启动并在日志里记一条，**不会阻止启动**。
- 该文件只存路径，不存任何数据内容；删掉它等于重置最近文件列表。

### 5.3 界面外观存在哪里

外观分两类，存在两个地方，因为它们的"归属"不一样：

| 位置 | 存什么 | 为什么 |
| --- | --- | --- |
| `.cdb` | 只有游戏数据 | 一个字节都不能因为换个配色而改变 |
| `.cdb.meta.json` | 这份文件的显示状态（列宽、颜色、窗口几何、**配色**） | 跟着文件走，换机器也保持 |
| `settings.json` | 应用级偏好（最近文件） | 宿主进程管的东西 |
| `localStorage` | 界面字号（`uiFontSize` / `gridFontSize`）与配色回退值 | 纯前端渲染参数，宿主不需要知道 |

- **字号**是"这台机器上这个用户的眼睛"：换一份数据、换一个窗口，都应该是同一个字号，
  所以放 `localStorage`。
- **配色**是"这份数据长什么样"：同时开两个库时靠颜色区分，把 `.cdb` 连同 `.meta.json`
  发给别人时对方看到的是同一套配色，所以放 side-car 的 `appearance.scheme`。

前端改配色时写两处：`localStorage`（给没有配色的文件当默认值）和宿主（落到当前文件的
side-car）。因此换一台机器、或删掉 `.cdb.meta.json` 只会丢配色、不会丢字号；反过来，
把 `.cdb` 发给别人也不会把「我习惯 18px」带过去，但会把配色带过去。

### 2.6 公共枚举 / 标志类型

```jsonc
"publicTypes": {
	"Rarity": { "kind": "enum",  "values": ["Common", "Rare", "Epic"] },
	"Tags":   { "kind": "flags", "values": ["hot", "cold", "wet"] }
}
```

- `kind` 只有 `enum` 与 `flags` 两种；`values` 的顺序就是枚举下标 / 标志位，允许空字符串
  表示「没有名字的那一项」，与 `typeStr` 的写法完全一致。
- 跟随公共类型的列在 `tables.<表名>.columns.<列ID>` 上记 `"publicType": "Rarity"`。这些列
  的 `typeStr` 仍然完整写在 `.cdb` 里，**且彼此完全相同**——所以文件在任何 CastleDB
  运行时里都是普通枚举，PalaceDB 负责让这些副本保持一致。
- 改一次定义（改取值、改名、改 enum/flags）会作为**一步撤销**同时改写所有绑定列的
  `typeStr` 与已存数据：取值按**名字**跟随，列表长度不变时按位置（即原地改名），
  删除取值时该格回落到第一项。打开文件时若发现某列与定义不一致，会按定义修回并提示。
- 删除公共类型只解除绑定，列保留已有取值，不会改写 `.cdb`。
- `autoIncrement`：`true` 表示这是一个自增整数列（`typeStr` 仍是普通的 `"3"`）。新增行、
  插入行、复制行、粘贴插入行时取「当前最大值 + 1」；新加列时已有行按 1..N 编号。手改
  单元格仍然允许，下一次插入仍按当前最大值继续。
