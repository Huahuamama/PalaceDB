# PalaceDB 开发者指南

> 给想改这个项目的程序员。用户手册见 `docs/03-用户手册-v1.md`，格式规范见
> `docs/05-数据与元数据格式规范-v1.md`。本文假设你已经会 C# 和 JavaScript，
> 关心的是「这东西怎么搭的、我改哪儿、别踩哪些坑」。

---

## 1. 它是什么

一个 **WPF 外壳 + WebView2 里的 HTML 前端 + 一个与界面无关的 Core 库**的桌面程序：

```
PalaceDB.exe (WPF, .NET 8)
 ├─ MainWindow.xaml.cs      窗口、WebView2 初始化、拖放、单实例/只读窗口
 ├─ EditorHost.cs           宿主：所有消息的处理、命令拼装、保存、备份
 ├─ EditorHost.Templates.cs 模板相关的宿主逻辑
 └─ WebView2 加载 web/index.html
       └─ js/app.js  壳（菜单、对话框、表列表、状态栏）
          js/grid.js 虚拟滚动网格 + 光标 + 选区 + 分隔条 + 展开面板
          js/editors.js  各列类型的编辑器（文本、下拉、颜色、图片…）
          js/subpanel.js 二级表格（List / Properties）
          js/bridge.js   postMessage 封装
          js/settings.js 字号 / 配色偏好

PalaceDB.Core.dll (.NET 8，不依赖 WPF)
 ├─ Model/         CdbObject / SheetData / Column / ColumnType / CdbValue
 ├─ Json/          CdbReader / CdbWriter（字节级往返）
 ├─ Commands/      所有编辑命令 + CommandStack（撤销）
 ├─ Document/      DatabaseDocument（打开、保存、备份、外部修改检测）
 ├─ Metadata/      MetaStore（.meta.json）、TemplateMeta、WindowPlacement
 ├─ Templates/     TemplateService（模板审计、套用、镜像）
 ├─ Editing/       ValueCodec / CellFormatter / SearchEngine / ClipboardService / TsvParser
 ├─ Merge/         三方合并与 .mine 冲突文件
 ├─ Cursor/        删除/撤销后的光标落点规则
 ├─ Storage/       AtomicFile（原子写盘）
 ├─ Media/         ImageResolver（缩略图与路径解析）
 ├─ Export/        LocalizationExporter（导出台词）
 └─ Settings/      AppSettings（最近文件等）
```

**为什么前端是 HTML 而不是 WPF 控件？** 十万行级别的表格要虚拟滚动、要自定义绘制和即时样式，
用 DOM + CSS 实现和调试的成本远低于 WPF 的虚拟化面板；代价是宿主与页面之间要有一套消息协议，
以及「谁拥有键盘」这类边界要自己处理（见 §11 陷阱）。

**为什么 Core 完全不带 WPF？** 所有规则（类型转换、命令、模板、合并、备份）都能用 xUnit 直接测，
端到端测试只需要验证「界面有没有把消息发对」。

## 2. 快速开始

```bash
# 构建（Debug）
dotnet build src/PalaceDB.App/PalaceDB.App.csproj

# 单元测试（704 项，秒级）
dotnet test tests/PalaceDB.Core.Tests/PalaceDB.Core.Tests.csproj

# 端到端（517 项，约 3 分钟，需要先 build）
python tests/ui/test_ui.py                        # 用 tests/fixtures/TestData2.cdb
python tests/ui/test_ui.py tests/fixtures/food.cdb
```

依赖：.NET 8 SDK、WebView2 Runtime、Python 3（只要 `websocket-client`）。

调试前端：设环境变量 `PALACEDB_CDP=9222` 启动，浏览器打开 `http://127.0.0.1:9222` 就能用
DevTools 检查页面。页面通过 WebView2 的虚拟主机从 `https://palacedb.local` 加载
（`MainWindow.xaml.cs` 里的 `SetVirtualHostNameToFolderMapping`），指向输出目录里的 `web/`。
`web/` 是原样复制到输出目录的，**没有构建步骤**，也没有打包器；改完重启程序即可，
或者用 CDP 发一次 `Page.reload`（浏览器快捷键被 `AreBrowserAcceleratorKeysEnabled = false`
关掉了，`Ctrl+R` / F12 都不响应）。

## 3. 数据模型

### 3.1 `CdbObject`

带**插入顺序**的字典（`CdbObject.cs`）。`.cdb` 是 JSON，键序是文件的一部分，
写回时不能重排，否则每次保存都会产生巨大 diff。`Set(null)` 删除键，`Rename` 保持位置。

### 3.2 `SheetData` / `Lines`

一张表 = `CdbObject Raw`（原始解析树，用于保存）+ `List<CdbObject> Lines`（行的内存视图）。

**这里有个历史坑**：早期版本只改 `Lines` 不写回 `Raw`，导致「加了行保存后消失」。
现在保存前 `SheetData.FlushLines()` 会按 `Lines` **整体重建** `lines` 数组
（`DatabaseDocument.PrepareForSave`）。任何新增的「行级」命令都必须只改 `Lines`，
不要自己去动 `Raw["lines"]`。

### 3.3 列与类型

`Column` 是表里一列的原始节点；`ColumnType` 是它的类型对象（`Enum`/`Flags` 带 `Values`，
`Ref` 带目标表名，`List` 带隐藏子表）。两者之间由 `ColumnTypeCodec` 的
`Decode(typeStr) → ColumnType → Encode → typeStr` 转换。

**类型字符串必须能被「解码再编码」保持语义**。同一个类型可以有多种写法：
`5`、`5:` 都是「没有取值的 Enum」；`5:,A,B` 是「第一项没有名字的 Enum」。
所以比较类型时用 `ColumnSpec.CanonicalTypeStr`（`Encode(Decode(x))`），不要比原文。

### 3.4 值

`CdbValue` 是 `Number / Str / Bool / Arr / Obj / Null` 的联合，数字保留原始文本
（`1.50` 不会变成 `1.5`），这是字节级往返的前提之一。

## 4. 读写：字节级往返

`CdbReader` / `CdbWriter` 的约定（`Json/`）：

- UTF-8 无 BOM，LF 换行，**Tab 缩进**，文件**末尾没有换行**。
- 空容器写成 `{}` / `[]`，不展开成多行。
- 数字原样输出（保留 `CdbValue` 里的原文）。
- 键序即插入序，不做排序。

`RoundTripTests` 会拿真实文件读进来再写出去，**逐字节比较**。这条测试是整个项目的地基：
只要它绿，就说明「打开再保存」不会弄脏别人的数据。任何改动序列化的代码，先跑它。

## 5. 命令与撤销

所有编辑都是 `IEditorCommand`（`Commands/IEditorCommand.cs`）：

```csharp
public interface IEditorCommand
{
    string Label { get; }                      // 撤销/重做菜单里显示的名字
    CursorAnchor? CursorBefore { get; set; }   // 执行前后光标在哪，撤销时用来回位
    CursorAnchor? CursorAfter { get; set; }
    void Execute();                            // 首次执行和每次重做都调它，所以状态要在构造函数里抓
    void Undo();
}
```

- `CommandStack`（容量 200）执行/撤销/重做；一次「结构性操作 + 光标」算一步。
- `CompositeCommand` 把多步合成一步（套模板 = 挂接 + 补列 + 重排）。
- 需要「没有实际改动就不进撤销栈」的命令，自己暴露一个 `IsNoOp` 属性
  （接口上**没有**这一项），调用方在入栈前判断，例如 `ColumnOps` 里的 `edit.IsNoOp`。
  用户在对话框里点 Apply 但什么都没改，不应该产生一条空的撤销记录。
- 命令里**只改内存**，不碰磁盘；保存由 `DatabaseDocument` 负责。

## 6. 宿主 ↔ 前端协议

页面 → 宿主：`send(type, payload)`，宿主在 `EditorHost.HandleMessage` 的 `switch` 里分发。
宿主 → 页面：`Send(new JsonObject { ["type"] = ..., ["payload"] = ... })`，
页面在 `app.js` 底部的 `onMessage` 里处理。

主要消息（新增消息时两边都要改，并在 `EditorHost.cs` 顶部注释里保持一致）：

| 方向 | 类型 | 说明 |
| --- | --- | --- |
| 页面→宿主 | `ready` | 页面加载完成，宿主回 `document` / `recentFiles` / `appInfo` |
| | `openFile` `openPath` `newDatabase` `save` `saveAs` `closeDocument` | 文件生命周期 |
| | `selectSheet` `requestRows` | 选表、按需取行（虚拟滚动） |
| | `setCell` `clearCells` `fillCells` `copyCells` `cutCells` `pasteCells` | 单元格编辑 |
| | `insertRow` `deleteRows` `duplicateRows` `moveRow` | 行 |
| | `addColumn` `editColumn` `renameColumn` `changeColumnType` `moveColumn` `deleteColumn` `convertColumn` | 列 |
| | `addSheet` `renameSheet` `deleteSheet` `moveSheet` `toggleSheetIndex` `toggleSheetGroup` | 表 |
| | `toggleSeparator` `setSeparatorTitle` | 分隔线 |
| | `applyTemplate` `extendTemplate` `detachTemplate` `saveTemplate` `renameTemplate` `deleteTemplate` | 模板 |
| | `setColumnWidth` `setStyle` `setColumnKind` `setColumnOptions` | 元数据 / 列选项 |
| | `undo` `redo` | 撤销栈 |
| | `copyText` | 把页面里选中的文字写到剪贴板 |
| 宿主→页面 | `document` `rows` `rowUpdated` `state` | 数据与刷新 |
| | `templateReport` `columnImpact` `mergeReport` `recentFiles` `appInfo` | 对话框数据 |
| | `cellRejected` `firstIssue` | 校验失败 / 状态栏错误 |
| | `images` `refOptions` `subValue` `browseResult` | 异步补数据 |
| | `clipboardWritten` | 复制完成后的提示 |

**payload 约定**：所有字段名是 camelCase（`column`、`sheet`、`row`、`columns`），
行号是 0 基下标，列用**名字**而不是下标——列可能被别的窗口改名。

## 7. 前端结构

| 文件 | 职责 | 改它之前要知道 |
| --- | --- | --- |
| `js/app.js` | 菜单、对话框、表列表、状态栏、快捷键、消息分发 | 2880 行，是全项目最大的一块；对话框都用 `openModal({build, onOk})`，`onOk` 返回 `false` 表示校验失败、不关窗；**不传 `onOk` 的对话框点 OK 直接关闭** |
| `js/grid.js` | 虚拟滚动网格：只渲染视口内的行、光标、矩形选区、分隔条、展开面板的占位 | 行高不固定（长文本会撑高），所有位置计算都过 `topOf(index)`；不要直接改 `style.top` |
| `js/editors.js` | 每种列类型的单元格编辑器：文本框 / 下拉 / 颜色 / 引用筛选 / 图片浏览 | 下拉框是页面里画的（`.cell-dropdown`），不是原生 `<select>` |
| `js/subpanel.js` | List / Properties 的二级表格（复用 `Grid`） | 二级表格锚定在**行号**上，行被移动/删除时会收起 |
| `js/settings.js` | 字号与配色偏好（localStorage） | 配色 id 必须和 `css/themes.css` 里的 `body[data-scheme="..."]` 对上 |
| `css/app.css` | 全部布局与组件样式 | 网格相关的高度都来自 CSS 变量 `--row-height` / `--head-height`，JS 会读它们 |
| `css/themes.css` | 九套配色 | 每套只覆盖变量，不写具体规则 |

### 虚拟滚动的算术

`grid.js` 里所有纵向位置都由这几个函数决定，改一个就要一起看：

```js
topOf(index)        = index * ROW_HEIGHT
                    + heightDeltaBefore(index)   // 前面被长文本撑高的行
                    + separatorShift(index)      // 前面的分隔条
                    + shiftBefore(index)         // 前面展开的面板
contentHeight()     = rowCount * ROW_HEIGHT + ... + separatorShift(rowCount)
panelTop(panel)     = topOf(panel.row) + heightOf(panel.row) + separatorShift(panel.row)
```

分隔条是**独立的一行**（`.sep-band`），画在它所属那一行的上方，把下面整体推一行；
它不属于任何数据行，所以点击它要映射到下一行（`rowIndexAt`）。

**行高只量一次，不要随手丢掉。** `rowHeights` 里存的是「这一行比基准行高多少」，
`contentHeight()` 靠它算滚动区总高。宿主每次保存 / 撤销 / 重做都会重发整份 document，
`setSheet` 因此会再跑一遍——如果这时清掉 `rowHeights`，视口上方的行全部退回基准高度，
滚动区一下变矮，浏览器会把 `scrollTop` 往上夹，这就是「保存后页面往上滚一点」。
所以 `setSheet` 用 `refreshing` 区分「同一张表的刷新」和「换了一张表」：前者保留行高、
保留 `scrollTop`/`scrollLeft`、也不做 `scrollIntoView`；后者才清零。
同理 `invalidate()` 默认**不**清行高，只有改字号（`applySettings`）才传
`{ remeasure: true }`——那时基准行高真的变了。

## 8. 元数据 side-car

`MetaStore` 管 `X.cdb.meta.json`：列宽、行底色、分隔线标题、配色、窗口几何、模板。
它按**列名**而不是下标匹配（列会被插入/删除），`Sync` 用四轮匹配把孤儿条目清掉。

写文件时用 `AtomicFile`（先写临时文件再替换），避免断电留下半个 JSON。

**不要把这些东西写进 `.cdb`**：游戏引擎会读到它们，而且会让数据文件产生无意义的 diff。
只有属于**数据定义**的东西（`props.displayColumn`、`props.separatorTitles`、列的可选/默认值）
才进 `.cdb`——判断标准是「游戏需不需要它」。

## 9. 模板系统

`TemplateService` 三个入口：

- `Audit(sheet, template)` → 缺列、顺序不同、多出列、类型/字段不一致、第二个 ID 列。
  **允许**缺列和顺序；其余是冲突，报告后什么都不改。
- `BuildApply` → 补列 + 重排（不删列、不写默认值）。
- `BuildMirrored` → 一张表里改列，回放到所有成员表，作为**一步**撤销。

模板存的是 `ColumnSpec`（列定义的快照），比较时一律走 `CanonicalTypeStr`。
新增列属性时，记得同时改 `ColumnSpec`、`TemplateMeta.From/ToSpec`、
`TemplateService.SameColumns`——漏一处就会出现「明明一样却说不一致」的 bug
（这个 bug 真发生过，见 `docs/06` §4.1c）。

## 10. 文档生命周期

`DatabaseDocument` 负责：

- 打开：读文件 → 解析 → 建 `Database` → 读 side-car → 检查有没有更新的备份。
- 保存：`PrepareForSave()`（`FlushLines`、重算 `index`/`group`）→ 原子写 → 删备份 → 清脏标记。
- 外部修改检测：记文件时间戳与长度，保存时若别人改过就提示；只读窗口每 2 秒轮询并自动重载。
- 多窗口：同一路径第二个窗口只读，靠 `OpenFileRegistry` 的写槽。写方窗口关闭时
  `DatabaseDocument.Dispose()` 释放写槽，`OpenFileRegistry.Released` 事件让其它窗口
  `TryTakeOverWriteSlot()` 接管（只接管「因为别的窗口占着」而只读的文档；元数据或磁盘
  只读的文档不会被解锁）。窗口关闭要调 `EditorHost.Detach()`，否则写槽会跟着进程留到
  下一次开窗。`OpenFileRegistry.DeferNotifications()` 用来在「先关旧文档、再开新文档」
  的空档里压住通知，免得别的窗口抢走刚腾出来的槽。
- 三方合并：打开时发现 `.mine` / `.r<N>` 就交给 `MergeResolver` + `ThreeWayMerge`。

## 11. 常见任务

### 加一种列类型

1. `ColumnType.cs`：加一个 `record`/`class`，给 `TypeId` 和 `TypeName`。
2. `ColumnTypeCodec`：`Decode` 的 `switch` 加一个 id，`Encode` 加一行。
3. `TypeDefaults`：新行的默认值。
4. `ValueCodec`：文本 ↔ 值的解析（编辑器的提交路径）。
5. `CellFormatter`：单元格显示文本 + 状态（ok/missing/error）。
6. `app.js` 的 `COLUMN_TYPES`：让列对话框能选到它。
7. `editors.js`：`openDropdown` / `begin` 里挑一个编辑控件；没有特殊控件就用文本框。
8. 单元测试：codec 往返、默认值、解析、格式化各一条；E2E 至少一条能编辑并写盘。

### 加一个菜单项 / 对话框

- 菜单在 `web/index.html` 的 `.menubar` 里，`data-action` 对应 `app.js` 的 `run(action)`。
- 右键菜单用 `showContextMenu(x, y, items)`，`items` 支持 `'sep'`、`{label, action, disabled, checked, submenu}`。
- 对话框统一 `openModal({ title, okLabel, wide, hideCancel, build, onOk, onCancel })`；
  `build` 返回 DOM 节点，`onOk` 返回 `false` 会留在对话框里（校验失败时用）。

### 查找 / 替换

- 搜索在**宿主**里跑（`Core/Editing/SearchEngine.cs`）：全文件要跨表，而前端只加载当前表；
  替换必须走 `CommandStack` 才能撤销，也只有宿主能写回并置脏。
- 搜索文本用**编辑器会拿到的文本**，不是表格的显示文本：布尔是 `true`/`false`（不是 `Y`/`N`），
  枚举是标签，引用是 id。否则「搜到 `Y` → 原样写回 `Y`」过不了 `ValueCodec.ParseText`。
- 全文件只走**可见表**：List / Properties 的内容已经在父单元格里，再搜隐藏子表会重复计数，
  替换还会改到用户看不到的地方。
- `Id`、`List`、`Custom` 可搜不可替：改 ID 会让所有引用失效，结构化值做子串替换会破坏 JSON。
- `Replace All` 按**单元格**去重（一个格子里多个命中只重写一次），整批一个
  `MultiCellEditCommand`，所以一次 `Ctrl+Z` 全部还原。
- 前端 `grid.searchHits` 只是 `"row:col"` 集合；`buildRow` 每次重绘都重新加
  `.search-hit` / `.search-current`，滚动或编辑后高亮不会丢。高亮用 `background-image`，
  不覆盖单元格自己的 `background-color`。颜色用**暖琥珀 / 橙**而不是 `--accent`：
  每套配色的分隔线就是 accent 色，早先用 `--selection-tint` 的命中会被看成一段分隔条；
  深色主题另有一套更亮的覆盖。
- `moveCursor(..., focus=false)`：查找时移动光标但不能把焦点从查找框抢走，否则输入到一半
  就断在网格代理上。

### 加一条宿主消息

`EditorHost.HandleMessage` 加 `case`，页面侧 `send('你的消息', {...})`；
需要回数据就 `Send(new JsonObject{...})`，并在 `app.js` 的 `onMessage` 里加 `case`。
**读 payload 一律用 `GetString` / `ReadIntArray` 这些辅助方法**，不要直接 `GetProperty`。

### 改配色

只改 `css/themes.css`：一套配色 = 一个 `body[data-scheme="id"]` 块，覆盖同一组变量。
新配色要在 `js/settings.js` 的 `SCHEMES` 里登记（id、显示名、明暗、三个色块），
否则设置窗口里看不到它。

## 12. 测试

### 单元测试（`tests/PalaceDB.Core.Tests`，704 项）

按子系统分文件，命名是「一句话说清断言」。加功能时先想「这条规则能不能不启动界面就测」——
能，就写在 Core 里测。`Fixtures.cs` 里有一份手工构造的小样本数据库。

### 端到端（`tests/ui/test_ui.py`，517 项）

启动真实的 `PalaceDB.exe`（`PALACEDB_CDP` 打开调试端口），通过 CDP 在真实 DOM 上操作：

```python
evaluate("__palacedb.send('addColumn', {...})")   # 直接调宿主消息
check("一句话描述", wait_for("...JS 表达式...", 10), 失败时打印的值)
```

页面暴露的钩子（`window.__palacedb`）：`state`（当前文档快照）、`send`、`run`（菜单动作）、
`grid`（行数、列、单元格值、光标）、`editor`、`applySettings`。

加检查的原则：**测用户看到的结果**（DOM 文本、单元格值、写盘后的 JSON），不要测内部变量。
每个 `check` 的说明写「用户能看懂的断言」，失败时打印的第三个参数要能定位问题。

### 测试数据

样本数据库在 `tests/fixtures/`。前两个**进仓库**，所以 clone 下来 `dotnet test` 就是全绿；
`food.cdb` 及其图片、文件目录是本机的真实样本，不进仓库：

```
tests/fixtures/
├── TestData1.cdb        266 KB，大表，单元测试的往返样本   ← 已提交
```

## 13. 构建与发布


## 14. 代码风格

- 注释和界面文案都是**英文**，注释解释**为什么**（尤其是看起来多余的判断），不复述代码。
- 私有方法按「文件里从上到下 = 从外到内」排列，`region` 不用。
- 字符串里的引号在代码中一律用 ASCII（`"` `'`），中文文档里才用全角。
- 公共 API 加 XML 注释；`PalaceDB.Core` 里不 `throw` 出用户看不懂的异常
  （用 `CdbFormatException` / `CdbValidationException`，消息要能直接显示给用户）。
- 一个命令一个文件/一个类，类名就是撤销栈里显示的名字。

## 15. 踩过的坑（改之前先读）

| 坑 | 现象 | 原因 / 正确做法 |
| --- | --- | --- |
| 行没写盘 | 加行后保存消失 | 只改 `Lines` 没 `FlushLines`；现在保存前统一重建 |
| 字节往返被破坏 | 每次保存都产生巨大 diff | 键序、数字原文、缩进、行尾；任何序列化改动都要跑 `RoundTripTests` |
| 类型比较用原文 | 「明明一样却说不一致」 | 用 `CanonicalTypeStr`；`5` 与 `5:` 同义 |
| 分隔条遮住下一行 | 第二行看不见 | 分隔条必须是**独立一行**，不能把它的单元格隐藏；`separatorShift` 的边界是 `<= index` |
| 枚举取值被裁剪 | `,1,2` 变 `1,2`，索引错位 | 空项是有意义的；`split(',')` 之后不要 `filter(Boolean)` |
| 剪贴板被表格抢走 | 对话框里复制到的是单元格 | `Ctrl+C` 前先看选区在不在 `#grid` 里 |
| 只读窗口仍能改 | 第二个窗口的编辑丢失 | 结构性消息都要先判 `_document.IsReadOnly` |
| 面板锚错行 | 展开的二级表格跑位 | 面板锚在**行号**上，行被移动/删除前先收起 |
| 编辑框比单元格小 | 双击后输入框浮在格子顶部 | 行高由**最高的那个格**决定；编辑框按 `heightOf(row)` 铺满，`textarea` 再取 `max(scrollHeight, 行高)`，并且要等它进了 DOM 再量 |
| 编辑后行背景色丢失 | 染过色的行，改一个格子后整行变回无色；切表再切回又有了 | `SendRowUpdated` 自己拼行节点、没带 `bg`（行与单元格背景），而批量 `SendRows` 带了；两处统一走 `BuildRowNode`，改哪条路径都不会再漏 |
| 查找搜不到看到的值 | 搜索 `Y` 找不到布尔格 | 搜索用**编辑器文本**（`true`/`false`），显示才是 `Y`/`N`；枚举用标签、引用用 id，理由同上 |
| 换主题后一操作就弹回旧配色 | Settings 里选完配色，插行 / 改列后又变回默认 | 设置窗口的实时预览用 `persist:false` 已经把 `state.settings` 改成新配色，OK 时 `scheme !== before.scheme` 恒为 false，`setFileScheme` 从没发出去，side-car 还是旧值；`applySettings` 增加 `syncFileScheme`，OK 时强制写文件 |
| 插行后分隔线错位 | 插入一行后，分隔线跑到别的行前面 | 分隔线存的是**行号**（`separators` + 平行的 `separatorTitles`），`RowInsertCommand` / `RowDeleteCommand` 原来只动 `Lines`；现在两个命令在构造时快照分隔线并平移（标题跟着走），撤销写回快照。删除时：范围前的线不动、范围首行的线保留（下一行顶上）、范围内的线随行删除、范围后的线前移，末尾不留悬空线 |
| 插行 / 删行后视窗跳动 | 插一行或删一行，页面滚到光标处 | `grid.setSheet` 原来把「行数变了」当成「换了张表」：scrollTop 归零、清掉已测行高，再 `scrollIntoView` 到记忆光标。现在**同一张表（名字相同）的刷新都保留 scrollTop/scrollLeft 和已测行高**，行数变化也算刷新；只有换表或换文件才重置（`setSheet(sheet, { resetView })`，`showDocument` 在 `payload.path` 变化时传 true） |
| 重复 ID 编辑时文本消失 | 单元格显示 `#DUP(id)`，双击编辑框却是空的 | `isMarker` 把所有 `#` 标记都当成「没有值」；`#DUP(id)` / `#REF(id)` 括号里就是原文本。新增 `markerText()` 把括号内容取出来作为编辑起始值，其余标记仍从空开始 |
| 纯数字 ID 被拒绝 / 复制后变成非法 ID | Id 输入 `123` 报错；复制数字 ID 的行得到 `123_2` | 校验原来只有 `IdentifierRegex`；现在 Id / Ref 接受 `^[0-9]+$`（`ValueCodec.IsValidId`），`PasteService.MakeUnique` 对纯数字追加数字后缀（`123` → `1232`，保留前导零），否则新 ID 会变成非法值 |
| 保存后视野往上跳 | 存一次 / 撤销一次就滚一点 | 重发 document 时别清 `rowHeights`，见 §7「行高只量一次」 |
| 只读窗口不解锁 | 关掉写方窗口后仍然只读 | 关窗要 `EditorHost.Detach()` 释放写槽，并监听 `OpenFileRegistry.Released` 接管 |
| 粘贴后光标跳回行首 | `Ctrl+V` 之后光标跑到该行第一格 | `RefreshAfterStructuralChange` 的两参数重载把光标写死在 `column = 0`，那是给增删行用的；粘贴要用三参数重载传回 `payload.column` |
| 折叠按钮跟着工具栏跑 | 收起表列表后按钮的屏幕位置跳变 | 按钮不能放进 `.toolbar`（侧栏收起时工具栏整体左移），也不能放进 `.sidebar`（会被 `display:none` 一起隐藏）；做成 `.body` 的绝对定位子元素 `position:absolute; left:4px; top:5px`，侧栏表头与收起态工具栏各留 42px 左内边距。因为它离开了工具栏，还要单独挂 `click` 监听 |

## 16. Fork 之后要改什么

1. **产品名与命名空间**：`PalaceDB` → 你的名字。需要同步改的地方：
   `src/*/` 的命名空间与目录名、`PalaceDB.sln`、两个 `.csproj`、
   `web/index.html` 的 `<title>`、`app.js` 里的标题、`App.xaml` 的资源名。
2. **数据目录**：`App.xaml.cs` 的 `ResolveDataFolder`（`%LOCALAPPDATA%\PalaceDB`）。
3. **文件扩展名 / 关联**：`.cdb` 是 CastleDB 的约定，改之前想清楚是否还要和它互通。
4. **图标与清单**：`app.manifest`、`MainWindow.xaml` 的 `Icon`。
5. **版本号**：`PalaceDB.App.csproj` 里的 `<Version>`（About 对话框显示的就是程序集版本，
   `EditorHost.Version()` 取 Major.Minor.Build）。
6. **许可证**：本仓库用 **CC0 1.0**（见根目录 `LICENSE`，等同放弃全部权利）。想换成
   MIT / Apache-2.0 这类软件许可证也可以，但要同时改 `LICENSE` 和 README 的「许可」一节。
   注意 CastleDB 本身是另一个项目，本程序只是读写它的文件格式，不包含它的代码。
7. **CI**：仓库里没有 CI 配置。最省事的是 GitHub Actions 上跑
   `dotnet build` + `dotnet test`；E2E 需要 Windows runner + WebView2，成本较高，
   可以只在本地跑。
