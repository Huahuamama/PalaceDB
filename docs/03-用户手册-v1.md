# PalaceDB 用户手册 v1

本文档面向使用本软件编辑 `.cdb` 数据表的策划与程序。

---

## 1. 安装与启动

### 1.1 运行环境

| 项目 | 要求 |
| --- | --- |
| 操作系统 | Windows 10 1809 或更高 / Windows 11 |
| 运行时 | .NET 8 Desktop Runtime |
| 渲染引擎 | Microsoft Edge WebView2 Runtime（Win11 自带，Win10 可能需要单独安装） |

若启动时提示 WebView2 初始化失败，请安装
<https://developer.microsoft.com/microsoft-edge/webview2/> 的 Evergreen Runtime 后重试。

### 1.2 启动方式

- 直接双击 `PalaceDB.exe`，进入欢迎页后点 **Open a database...**。
- 把 `.cdb` 文件拖到窗口里。
- 命令行带参数：`PalaceDB.exe D:\data\Game.cdb`。
- 在资源管理器里把 `.cdb` 的默认打开方式设为 `PalaceDB.exe` 后双击文件。
- **File ▸ New Database**（`Ctrl+N`）：新建一个空库，见 §1.3。
- **File ▸ Open Recent**：最近打开过的数据库，最新的排在最前。

同一个 `.cdb` 可以在多个窗口同时查看，但**同一时刻只有一个窗口可写**，其余窗口以只读模式打开（详见 §7）。

### 1.3 新建数据库

**File ▸ New Database**（`Ctrl+N`）打开一个名为 `Untitled` 的空库：左侧表列表为空，
表格区提示 **Add a table...**，点它（或侧栏的 `+`）就能建第一张表。

新库**还没有文件**，所以：

- 标题栏显示 `Untitled *`，文档始终是「未保存」状态。
- `Ctrl+S` 会先弹出另存为对话框选择落盘位置，不会静默写到临时目录。
- 在选好位置之前，**不会**产生自动备份文件（没有文件可恢复）。
- 另存为成功后，文档就变成普通文件：标题换成文件名，脏标记清除，进入最近文件列表。

### 1.4 最近文件

**File ▸ Open Recent** 是一个子菜单，每条记录左边是文件名、右边是所在目录（鼠标悬停看完整路径）。

- 最多记 10 条，重复打开同一个文件不会产生两条，只会把它挪到最前。
- 列表存在 `%LOCALAPPDATA%\PalaceDB\settings.json`，与 `.cdb` 无关；删掉这个文件就等于重置。
- 若某个文件已经被删除或移动，它仍然会显示（灰色斜体），**点一下即从列表里移除**并提示。
- 底部的 **Clear Recent Files** 一次清空整个列表。

## 2. 界面总览

```
┌──────────────────────────────────────────────────────────┐
│ File  Edit  View                          Game.cdb        │ 菜单栏
├──────────────────────────────────────────────────────────┤
│ ⊞ ⊟ ⊟ │ ⧉ ✂ 📋 │ 🖌 ▾ ✓ ✕                          ⚙ │ 工具栏（图标）
├────────────┬──┬──────────────────────────────────────────┤
│ TABLES  + «│  │ Id │ Title │ Des │ …                     │ 表头
│ EventCard  │1 │ vocational │ 职业培训 │ …                │
│ Location   │2 │ college    │ 社区大学 │ …                │ 表格区
│ …          │… │                                          │
├────────────┴──┴──────────────────────────────────────────┤
│ EventCard │ R1 C1 │ 104 rows │ 错误提示     Editable     │ 状态栏
└──────────────────────────────────────────────────────────┘
```

- **左侧表列表**：当前数据库的所有可见表，括号中的数字是行数。右上角 `+` 新建表，`«` 折叠（`Ctrl+B`）。
  跟着表格模板走的表，名字后面有一个小圆点，鼠标停上去才说明模板信息（见 §6.4）。
- **折叠后列表完全隐藏**，横向空间全部让给表格；工具栏最左侧出现 `⊞` 按钮（`Ctrl+B` 同效）把它展开回来。
- **行号列**：表格最左侧的窄列显示行号（约 28px，够放三位数，更长的直接截断），单击行号即选中整行；按住行号上下拖动可以把整行
  搬到新位置（拖动时会画出一条落点线），右键行号弹出该行的操作菜单。
- **行高自适应**：单元格里的文本会自动换行，**行也会跟着长高**，直到把整段文字显示完
  ——不需要拉宽列或去悬停看 tooltip。只有需要更多空间的行才变高，单行内容的行保持原样；
  变高的行会把下面的行和展开的二级表格一起推下去。单个值最多显示约二十行，
  更长的文本仍可在 tooltip 或编辑器里看全。
- **状态栏**：当前表名、光标位置（或 `N x M` 选区大小）、总行数、**第一个校验错误**（表名 + 第几行 + 原因，如 `EventCard · Row 1: Duplicate identifier 'vocational'`）、读写状态（鼠标悬停可看只读原因）。当前表跟着模板走时，右侧还会显示 `Template: 模板名`。
- **工具栏最右侧的设置按钮**：打开设置窗口，调界面字号、表格字号和配色（见 §9.1）。

## 4. 编辑单元格

双击单元格、按 `Enter` / `F2`，或直接键入字符即可进入编辑。`Enter` 提交，`Esc` 取消。
打开后光标停在文本末尾（不会全选，否则看不出可以继续输入）。

| 列类型 | 编辑方式 |
| --- | --- |
| Text / Id / Formula / Guid | 文本输入框；Text 列是可自动增高的多行编辑框（见 §4.4） |
| Int / Float | 文本输入框（非法输入会被拒绝并提示） |
| Bool | 直接切换 `Y` / `N`（双击或空格） |
| Enum | 下拉列表；**输入数字时按标签匹配**（值为 `1,2,3` 时输入 `2` 得到标签 `2`，不是第 3 项） |
| Flags | 多选下拉（复选）；写回的是名字（`meat,dairy`），也接受位掩码 |
| Ref（引用） | **输入框 + 过滤列表**：直接在格子里输入即过滤目标表的行，`↑`/`↓` 选择、`Enter` 取用，也可以点列表项 |
| Color | **调色板弹层**：24 个预设色块 + 原生取色器 + `#RRGGBB` 输入；表格中显示色块本身而不是十六进制值 |
| Image / File | 文本输入 + `...` 浏览按钮（存**相对路径字符串**，不生成 `.img` / `timage` 文件）；选完立即写入单元格 |
| List / Properties | **单击单元格在行下展开二级表格**（再点一次收起），见 §4.2 |

弹层（枚举 / 标志 / 引用 / 调色板）贴在单元格下方，靠近窗口边缘时会自动翻转或左移，
不会被表格的滚动区域裁掉；表格滚动时弹层跟着单元格走。

### 4.1 多单元格编辑

选中一片区域后：

- 按 `Delete` / `Backspace`，或 Edit ▸ **Clear Cells**：清空整片区域（一次撤销）。
- 工具栏 **Fill** 选颜色 → 选作用域（Cell / Row / Column）→ **Apply**：给整片区域上色。
- `Ctrl+C` / `Ctrl+X` / `Ctrl+V`：整片复制、剪切、粘贴。
- 这三个快捷键**只在表格上有选区时属于表格**。在对话框里、状态栏里选中文字后按 `Ctrl+C`，
  复制的是那段文字（例如错误信息、冲突报告），不会再把表格里选中的单元格塞进剪贴板；
  对话框打开时 `Ctrl+V` 也是普通粘贴，文本会进到对话框的输入框里。

### 4.2 List / Properties 结构化编辑

List 与 Properties 列由一张**隐藏子表**支撑（`表名@列名`，写进 `.cdb` 时带 `"hide": true`）。
新建这类列时在同一个对话框里声明字段；已有的列在 **Edit Column** 里改字段列表。

**单击单元格**就在这一行下面展开二级表格，再点一次收起。二级表格是插进行里的：原本的
下一行会往下让开，所以编辑时始终能看到自己改的是哪一行，也不会挡住别的列。

二级表格就是一张真正的表格，用的是和一级表格同一套网格与编辑器：

- 有表头（字段名 + 类型）、行号栏、单元格光标框；方向键 / Tab / Enter / Home / End
  都按表格习惯移动，`Delete` 清空选中的格子。
- 单元格**双击**进入编辑，也可以直接打字。按字段类型给控件：Text/Image/File 文本框、
  Int/Float 数字框、Bool 单击切换、Enum / Flags 下拉、**Ref 下拉（可打字筛选，
  列出目标表的行）**、Color 调色板。
- 编辑即时写回，**没有 Done 按钮**：改动在停止输入约 0.25 秒后提交，收起面板、保存、
  撤销之前都会先把未提交的改动写完；整次修改仍然是一步撤销。
- 工具栏 **+ Row** 追加一行、**- Row** 删除光标所在行；Properties 固定一行，没有这两个按钮。
  行号栏同样可以按住拖动，把某一条记录搬到别的位置（整条记录跟着走，不是只换顺序标签）。
- 工具栏 **Fields...** 打开该列的字段编辑器（增删改字段、改字段类型、改引用目标、调整字段顺序），
  也就是一级表格里 Edit Column 的同一张表单。点 **Apply** 后字段真的会改：面板表头当场换成
  新字段，已经写进单元格的数据跟着字段走——改名保留原值、删字段丢掉那一列、新字段按类型补默认值。
- 展开状态下，一级表格里这一格显示 `…` 而不是原来的文本：内容已经在下面展开着，重复一遍只会
  让人以为它们是两份数据。收起面板后原值立刻回来。
- **可以同时展开多个**：不同行的 List 各自一个面板；同一行有两个 List 列时也能同时展开，
  第二个面板排在第一个下面。点哪一格就收起哪一个。
- 子表内 `Ctrl+C` / `Ctrl+X` / `Ctrl+V` 在二级表格内部复制粘贴，不会动到一级表格的选区。
- 子表中嵌套的 List / Properties 列不在二级表格里显示，需到子表中编辑。

### 4.3 粘贴的两种模式

| 命令 | 行为 |
| --- | --- |
| **Paste**（`Ctrl+V`） | 从光标处**覆盖**已有单元格，行数不够时不会新增行。光标在 ID 列上时整列 ID 会被覆盖；光标在数据列上时不会碰到 ID |
| **Copy**（`Ctrl+C`） | 复制**选中的那些列**，包括 ID 列和颜色等任意类型；`Ctrl+X` 剪切后再粘贴是移动 |
| **Insert Paste**（`Ctrl+Shift+V`） | 在光标行**插入**新行再写入，不覆盖任何已有数据；ID 冲突自动加 `_2` 后缀 |

两者都是独立的撤销单元。

**从别的程序粘贴**：从 Excel / WPS / 文本编辑器复制的**纯文本表格**（制表符分隔、换行分行）
可以直接粘贴。解析遵循电子表格惯例：带引号的字段、`""` 转义、单元格内部的制表符与换行、
CRLF 行尾、文件开头的 BOM 都能正确处理。整块从光标列开始往右铺开；
若块比可用列宽、或某个单元格无法转换成该列类型，**整次粘贴被拒绝并提示**具体是第几行第几列。

**ID 列**：把光标放在 ID 列上粘贴，粘的就是 ID（可以一次贴一整列标识符）；
光标在右侧的数据列上粘贴时，块不会往回吃到 ID 列。重复的 ID 会在状态栏报出来（见 §2）。

### 4.4 多行文本

Text 列的编辑框可以装下换行，方便写台词、描述这类长文本：

- 编辑框随内容自动增高，不会把文字挤在一行里滚动；**长行在编辑框里自动换行**，不会藏到右边看不见的地方。
- `Shift+Enter` 插入换行，**直接按 `Enter` 仍然是提交**并跳到下一行单元格。
- **编辑中 `↑` / `↓` 在文本内部移动光标**，不会跳到相邻单元格；要换格子用 `Enter`、`Tab` 或 `Alt+↑` / `Alt+↓`。
- 表格里的长文本会自动换行，**行也跟着长高**，直到整段文字都显示出来（见 §3）；完整原文始终在 tooltip 里。
- 换行是真正的换行，不再显示成 `↵` 标记。
- 值原样写回 `.cdb`（`\n` 会被 JSON 转义），导出、复制都不受影响。
- 用中文/日文输入法时，按回车选词**不会**误提交单元格（输入法组字期间的按键被忽略），
  选完词再按一次回车才提交。

## 5. 行操作

工具栏、单元格右键菜单、**行号右键菜单**都提供：

| 操作 | 说明 |
| --- | --- |
| **+ Row**（工具栏） | **在表尾追加一行**（不管光标在哪一行），光标跳到新行 |
| Insert Row Above / Below / **Insert Row Here**（行号右键） | 在光标行之前 / 之后插入空行，各列取类型默认值（Ref 取目标表首行 ID，Guid 自动生成）；**ID 列留空**，由作者自己填，空 ID 会在状态栏提示 |
| **Add Row**（行号右键） | 在表尾追加一行 |
| Duplicate | 复制选中行（ID 自动改名保证唯一） |
| Delete | 删除选中行 |
| **按住行号上下拖动** | 把整行拖到新位置；拖动时画出一条落点线，靠近上下边缘会自动滚动 |
| `Ctrl+Up` / `Ctrl+Down` | 上下移动光标所在行 |

移动行是一步撤销；移动时已经展开的二级表格会先收起（它锚定的是行号，不是记录，否则会显示成另一行的数据）。

**删除后光标不会跳回 (0,0)**：会落在原位置的下一个行；如果删除的是最后一行，则落在新的最后一行（需求 R3）。

### 5.1 分隔线

分隔线用来把一张长表切成若干组，只影响显示与写盘，不影响数据。

| 操作 | 入口 |
| --- | --- |
| 在光标行**之前**插入分隔线 | 行右键 ▸ **Add Separator** |
| 删除该行的分隔线 | 行右键 ▸ **Remove Separator** |
| 给分隔线命名 | 行右键 ▸ **Name Separator...** |

- 表格中显示为**独占一行高的分隔条**（浅色底 + 顶部一条蓝线），画在该行**上方**；下面的行整体下移一行，不会被盖住。
- 命名后名字写在分隔条里（未命名时就是一条空的分隔条）；鼠标悬停同样可看到标题。
- **分隔条不会吞掉任何内容**：它下面的那一行照常显示自己的值、照常可以选中编辑，值长了也照样把行撑高。
- 命名会写入 `props.separatorTitles`，与 `separators` 数组一一对应且自动排序。
- 增删和命名都可以用 `Ctrl+Z` 撤销。

## 6. 表与列的结构编辑

### 6.1 表

- 左侧表列表右上角 `+`，或在表上右键 ▸ **Add Table...**：新建表（自带一个 `id` 列）。
- 表右键 ▸ **Table Settings...**：表的名称与模板都在这个窗口里改。改名字会同步改隐藏子表（`Table@Column`）与指向它的引用列；改名与套用模板可以一次做完。
- 表右键 ▸ **Delete Table**：删除表及其隐藏子表；指向它的引用列会降级为文本列（值保留）。可用 `Ctrl+Z` 撤销。
- 表右键 ▸ **Move Table Up / Down**：调整表的顺序（List / Properties 列的隐藏子表会跟着一起移动）。

表名规则：以字母或 `_` 开头，只能包含字母、数字、`_`。

**生成字段（Add Index / Add Group）**：表右键的两个勾选项，给每行额外生成一个数值字段，
供游戏端直接读取，不需要在表里手写这两列：

| 菜单项 | 生成什么 |
| --- | --- |
| Add Index | 每行写 `index`，等于它在表中的行号（0 起） |
| Add Group | 每行写 `group`，从 0 开始，**每遇到一条带标题的分隔线就 +1** |

两者都在**保存时**按当前行序重算，所以插入、删除、移动行之后不需要手工维护。
`group` 依赖分隔线的标题（见 5.1），表里一条带标题的分隔线都没有时不会写出 `group`。
两个开关都是可撤销的。

### 6.2 列

在**表头**上右键：

| 菜单项 | 说明 |
| --- | --- |
| Insert Column... | 在当前列右侧插入。对话框可选名称、类型；Enum / Flags 填逗号分隔的取值；Ref 选目标表；List / Properties 声明字段列表；还可设可选字段（见 §6.2.3） |
| Edit Column... | **一个对话框改完**：名称、类型、字段列表、必填 / 默认值 / 显示格式 / 可本地化。整个修改算**一次撤销** |
| Move Column Left / Right | 调整列顺序 |
| Convert ▸ | 整列批量转换值，见 6.3 |
| Delete Column | 删除列及其所有值，可用 `Ctrl+Z` 撤销。**ID 列也可以删**——删掉之后这张表没有主键，指向它的引用会解析失败，这是作者的选择。唯一的例外是"这张表只剩这一列"：没有列的表没法编辑，此时会提示先加一列再删 |
| Display Column of 'X'... | 仅引用列可用：选目标表用哪一列作为下拉框显示文本 |
| Icon Column of 'X' | 仅 Image / Text 列可用：把该列设为目标表的图标列（勾选项，再点一次取消），见下 |
| Localizable | 仅 Text / Id 列可用：勾选后该列进入台词导出（勾选项，再点一次取消），见 6.2.2 |
| Clear Column Colour | 清除该列背景色 |

所有结构编辑都是可撤销的。

**Enum / Flags 的取值可以有一项没有名字**。取值按逗号分隔，逗号之间留空就是「无名字的
取值」：`,1,2` 是三项（第一项没有标签），`1,,3` 是中间一项没有标签，`1,2,` 是最后一项
没有标签。留空是**有意义的**——CastleDB 用它表示「这一格是空的」；单元格里存的是序号，
所以删掉这一项会让所有已存的序号错位到下一个标签上。对话框会原样保留空白项，下拉框里
这一项显示为灰色的 `(empty)`，可以正常选中。Flags 里的空白项同样是一个真实的位。

**显示列**：默认引用下拉框显示目标行的 ID。若目标表设置了显示列，下拉框会显示
「id - 显示值」。该属性保存在**目标表**的 `props.displayColumn` 上，所以菜单项写作
`Display Column of 'Item'...`。

**图标列**：下拉框里每条记录的左侧还能显示一个小图标。把某一列设为图标列后，该列
存的值（图片路径）会被读出来画在下拉框里。它同样保存在**目标表**的
`props.displayIcon` 上，菜单项写作 `Icon Column of 'Item'`，是一个勾选项：

- 图标列和显示列**互相独立**，可以同时设置，一条记录既有图标又有文字标签。
- 该列某行为空、或图片文件不存在时，下拉框里保留一个虚线空位，其余行不受影响。
- 这两个属性都属于数据定义，保存在 `.cdb` 里（不是 `.meta.json`），换台机器打开也有效。

### 6.2.1 图片列与缩略图

图片列（typeStr `7`）存的是**图片路径字符串**，不复制文件、不生成 `.img`：

- 单元格里先画 20px 缩略图，后面跟路径原文，方便一眼认出是哪张图。
- 相对路径按 **`.cdb` 所在目录**解析，与游戏引擎读表时的约定一致；绝对路径直接用。
- 支持 png / jpg / jpeg / gif / webp / bmp / svg。单个文件超过 4 MB 不预览（避免
  卡住界面），单元格仍显示路径。
- 文件找不到时显示虚线框 + 警告色文字，不会影响其它行，也不会报错。
- 同一个路径在一次会话里只读一次盘；文件被覆盖后（大小或修改时间变了）会自动重读。
- 编辑时点单元格右侧的 `...` 打开系统文件选择框，选完只写入路径。

### 6.2.2 台词（Localizable）与导出

给「会说给玩家听」的文本列打上 `Localizable` 标记，就能把它们一次性导出成翻译用的 XML。

1. 在表头右键 ▸ **Localizable** 勾选（列上会显示标记）。这是列定义的一部分，写回 `.cdb`，可撤销。
2. File ▸ **Export Localized Texts...** 选择保存位置。

导出结构（与原版 CastleDB 的 `Lang.buildXML` 一致）：

```xml
<cdb>
	<EventCard>
		<college>
			<Title>College</Title>
			<Des>...</Des>
		</college>
	</EventCard>
</cdb>
```

- 文件是 **UTF-8 带 BOM**，老一些的翻译工具靠 BOM 认编码。
- 单行文本内联，多行文本按缩进整块写出。
- 表名、行 ID、列名会做 XML 名称合法化（非法字符换成 `_`，数字/`.`/`-` 开头补 `_`）。
- 一个可导出列都没有时，会提示「This database has no localizable columns...」并且**不写文件**，避免生成空 XML 覆盖上一次的成果。

### 6.2.3 列的可选字段

**Insert Column...** 与表头右键 ▸ **Column Options...** 共用同一组可选字段：

| 字段 | 适用类型 | 作用 |
| --- | --- | --- |
| **Optional**（可选） | 全部 | 勾选后该列允许空值；不勾时空值会被判为校验错误 |
| **Default**（默认值） | 全部 | 新增行时写入该列的初始值；留空则按类型取默认值（Int/Float `0`、Bool `N`、Ref 取目标表首行…） |
| **Format** | Int / Float | 选 **Percent** 时单元格按百分比显示（存的是原值，只影响显示） |
| **Localizable** | Text / Id | 勾选后该列进入台词导出（见 §6.2.2） |

- 默认值在**插入新行**时生效；对已有行改默认值不会回溯改写它们的数据。
- 修改已有列的默认值**不会**动已有数据，只影响之后插入的行。
- 这些字段（`opt` / `default` / `display` / `kind`）都属于**数据定义**，写进 `.cdb`；
  而列宽、背景色属于显示状态，写进 `.meta.json`。
- 一次 Column Options 修改是**一个撤销单元**，`Ctrl+Z` 整体还原。

### 6.3 列值批量转换（Convert）

在表头上右键 ▸ **Convert**，可对整列的值一次性做同样的改写。整列算**一步撤销**。

| 列类型 | 可选转换 | 效果 |
| --- | --- | --- |
| Id / Text | `lowercase` | 全部转小写 |
| | `UPPERCASE` | 全部转大写 |
| | `UpperIdent` | 首字母大写，其余不变 |
| | `lowerIdent` | 首字母小写，其余不变 |
| Enum / Flags | 同上四项 | 改的是**列定义里的取值表**，单元格存的是索引，所以数据行不动 |
| Int / Float | `* 10` | 全部 ×10 |
| | `/ 10` | 全部 ÷10（Int 列向零取整，`5 → 0`） |
| | `+ 1` / `- 1` | 全部 +1 / −1 |

几点注意：

- **空单元格和缺失值不参与转换**（与「值本来就没有」保持一致）。
- **转换 Id 列会同步重定向全库的引用**：所有指向该表的引用列会跟着改成新 ID，引用
  不会断。若转换后会出现**重复 ID**（例如同时存在 `Sword` 和 `SWORD` 再转大写），
  操作会被拒绝并提示是哪两行冲突，此时先改名再转换。
- 已经是目标形式的值会被跳过，所以重复执行同一转换不会产生多余的撤销步骤。
- 转换不改变列类型，也不改变行数，光标停留在原处。

### 6.4 表格模板

**模板**是一份命名的列定义清单，存在 `.meta.json` 里（不写进 `.cdb`，游戏端读不到它）。
跟着同一个模板走的几张表，列的**所有设置**保持一致：名称、类型、必填、默认值、显示格式、
Enum / Flags 的取值表、List / Properties 的字段、文档说明。

**创建**

- 表右键 ▸ **Table Settings...** ▸ **Save these columns as a new template...**，输入名字。
  当前这张表的列会成为模板的定义，并且这张表立刻开始跟着它走。
- 表右键 ▸ **Table Settings...** ▸ 顶部 `+` 新建表时，对话框里可以直接选一个模板，
  新表按模板的列建好并自动挂上去。整个动作是**一步撤销**。

**跟着模板走的时候**

- 在任意一张成员表里改列（改名、改类型、加列、删列、调顺序、改列选项），
  改动会**同时作用到所有成员表**，并且整体算**一步撤销**。完成后提示里会写明还改了哪几张表。
- 删除列、或把类型换成数据不兼容的类型时，如果别的表里还有值，会先**二次确认**：
  对话框列出每张表有多少行受影响、一共会丢掉多少个值，确认后才执行。
- 模板的定义是**派生态**：它总是跟着最近一次编辑的那张成员表走，所以不需要手工同步。
  `Ctrl+Z` 撤销列改动时，模板定义也一起回到之前的样子。

**套用模板**（已经建好的表）

表右键 ▸ **Table Settings...** ▸ **Template** 选一个模板，点 **Apply**。套用前会先检查：

| 情况 | 结果 |
| --- | --- |
| 和模板完全一致 | 直接套用 |
| 缺少一些列 | 允许：缺的列按模板顺序补在正确位置，**已有行的这些列留空**，不写默认值 |
| 列的顺序不同 | 允许：按模板顺序重排，数据跟着列走 |
| 多出模板没有的列 | 拒绝，并弹出报告 |
| 同名列的类型 / 字段不一致 | 拒绝，并弹出报告 |

类型比较按**规范形式**进行：同一个类型在文件里可能写成 `5` 或 `5:`，这两种写法视为同一个类型，
不会被当成冲突。真正不一致时，报告会写清楚差在哪：Enum / Flags 列出两边的取值
（如 `lists ('', 'Common', 'Rare') in this table but ('Common', 'Rare') in the template`），
Ref 写出各自指向的表，其它类型写出各自的类型名。

被拒绝时**什么都不会改**。报告里如果只列出「多出来的列」这一类冲突，会多给一个按钮
**Add these columns to the template**：把这些列加进模板，其它成员表跟着补上这些列，
数据不丢。这是唯一能靠「改模板」解决的冲突，其它冲突必须先手工改列。

选 **None (stand alone)** 则脱离模板，列和数据都保持不变。

**界面上的提示**

- 左侧表列表里，跟着模板走的表名字后面有一个小圆点；鼠标停上去才显示模板名、
  列数和「有几张表在用」。圆点变成警告色表示这张表和模板不一致（用 Table Settings 修）。
- 状态栏右侧显示 `Template: 模板名`，没有模板时不占位置。
- View ▸ **Templates...** 打开模板列表：可以改名，也可以删除。删除模板**不会**动任何表，
  它们只是不再跟着它走，列和数据都留着。

模板本身不进撤销历史（它可能被别的表用着），但「这张表开始 / 停止跟着模板」是可撤销的。

## 7. 多窗口与只读

- **File ▸ New Window**（`Ctrl+Shift+N`）打开一个全新窗口。
- 每个窗口有**独立的文档状态和独立的撤销历史**。
- 同一个 `.cdb` 在第二个窗口打开时会变成**只读**：
  - 状态栏显示 `Read only`，鼠标悬停显示原因；
  - 打开时弹出提示 `Opened read-only: it is already open in another window.`；
  - 所有编辑命令被拒绝，不会写盘。
- 关闭第一个窗口后，再打开该文件即可编辑。
- 文件本身带只读属性、或元数据文件要求只读时，也会以只读方式打开。

## 8. 保存、备份与恢复

- **显式保存**：`Ctrl+S`。不做自动保存（需求 Q1=C）。
- **未保存标记**：标题栏与文档名后的 `*`。
- **自动备份**：文档有未保存修改时，每 5 分钟写一次 `X.cdb.autobackup`（**只保留 1 个**）。
  第一次写出时会提示一次，之后不再打扰。
- 保存成功后备份文件会被删除。
- 关闭窗口/关闭文档时若有未保存修改，会询问「保存 / 不保存 / 取消」。
  - 选「不保存」时备份也一并删除（你已明确放弃这些修改）。
- 保存采用**原子写入**（临时文件 + `File.Replace`），断电或崩溃不会产生半截文件。

> 注意：列宽、背景色属于「显示状态」，改动会**立即**写入 `X.cdb.meta.json`，不会让 `.cdb` 变成「未保存」。

### 8.1 崩溃恢复

程序被强制结束（任务管理器、断电、蓝屏）时，`.autobackup` 会留在磁盘上。
**下次打开这个文件时**，如果备份比主文件新，会弹出询问：

| 选择 | 结果 |
| --- | --- |
| Yes | 用备份覆盖主文件，未保存的修改回来了（此时文档是「已保存」状态） |
| No | 丢弃备份，打开磁盘上已保存的版本 |
| Cancel | 不打开这个文件 |

恢复前会先校验备份是不是合法文档，**校验失败就放弃恢复**，绝不会用好文件换坏内容。
如果备份比主文件旧（比如上次是正常关闭的），会被静默删除。

### 8.2 外部修改检测

程序每 2 秒检查一次当前文件的修改时间。如果文件被别的程序（Git、另一个编辑器、
同步盘）改过：

- **本窗口没有未保存修改** → 自动重新加载，右下角提示「Reloaded because the file was changed on disk.」
- **本窗口有未保存修改** → 弹窗询问：重新加载会丢弃本地修改，是否继续？
  - 选「否」保留本窗口内容，并记住这次外部改动，不再反复弹窗（直到下次外部改动）。

这条机制也让**只读窗口**（同一个文件在第二个窗口打开时）自动跟上第一个窗口的保存。

> 文件被外部删除不算冲突：程序继续用内存中的内容，下次保存会重新创建文件。

### 8.3 与 Git 冲突共存（`.mine` 三方合并）

两个人在各自的分支上改了同一个 `.cdb`，git 合并时会留下冲突。本程序在**打开文件时**
自动识别并处理，不需要手工去编辑 JSON：

| 磁盘上的情况 | 处理方式 |
| --- | --- |
| 有 `X.cdb.mine`（+ 可选的 `X.cdb.r1`、`X.cdb.r2`…） | `.mine` 是本地版本，工作文件是对方版本，最旧的 `.r<N>` 当作共同祖先 |
| `X.cdb` 里含 `<<<<<<<` 冲突标记 | 每一段的两半分别当作本地 / 对方版本 |

合并规则：

- 只有一边改过的值 → 直接采用那一边。
- 两边改成同一个值 → 不算冲突。
- 两边改成不同的值 → **保留本地值**，并在「Merged with conflicts」里逐条列出
  `路径 / 本地 / 对方 / 祖先`，由你决定要不要手动改回去。
- 行与列按 **ID / 名称** 配对，不按数组下标：一边插了一行，另一边其它行的修改不会错位。
- 一边删、另一边改同一行 → 视为冲突，保留改过的那份，绝不悄悄丢掉工作。

合并结果会以**未保存**文档打开（标题带 `*`）。确认无误后 `Ctrl+S`：

- 写入合并后的内容；
- 然后才删除 `.mine` 与 `.r<N>`，冲突文件不会在保存前被清掉；
- 如果另存为其它路径，原来的冲突文件保持不动。

没有 `.r<N>` 时降级为两方比较：只能判断「两边是否一致」，不一致就报冲突并保留本地值。

## 9. 显示设置

| 功能 | 入口 |
| --- | --- |
| **设置窗口** | View ▸ Settings...（`Ctrl+,`），或工具栏最右侧的设置按钮 |
| 深色模式 | View ▸ Dark Mode（`Ctrl+T`），在浅色与深色之间快速切换；具体用哪套配色在设置窗口里选 |
| 折叠/展开表列表 | 工具栏最左侧的按钮，或 `Ctrl+B`，或焦点不在表格里时按 `Tab`。展开和收起是**同一个按钮、同一个位置、同一个大小**，只有箭头方向翻转 |

### 9.1 设置窗口

窗口分三块，改动**立刻生效**——窗口本身就是预览，顶部那张小表格用的就是真实表格的
样式变量，所以字号和配色在点 Done 之前就能看清效果：

| 设置项 | 范围 | 默认 | 说明 |
| --- | --- | --- | --- |
| 界面字体大小 | 12–20 px | 15 px | 菜单、工具栏、对话框、状态栏 |
| 表格文本大小 | 10–20 px | 14 px | 表头、单元格、行号；行高会跟着放大，两行文本仍放得下 |
| 配色方案 | 9 套 | Daylight | Daylight 浅色 / Midnight 深色 / Graphite 中性灰 / Deep Sea 深蓝 / Sandstone 暖米 / Blush 粉 / Lilac 淡紫 / Olive 橄榄绿 / Mint 薄荷绿 |

- **Cancel 是真正的撤销**：在窗口里试了字号或配色又不想留，点 Cancel 会回到打开窗口
  前的样子；点 Done 才记住。
- **Restore defaults** 一键回到 15 px / 14 px / Daylight。
- **字号是全局的，配色是随文件的。** 字号存在本机（浏览器本地存储），换文件不变；
  配色写进这个文件的 `X.cdb.meta.json`（`appearance.scheme`），所以同时开两个库时，
  窗口颜色能帮你分清哪个是哪个。没选过配色的文件沿用上次的选择。
- 两者都**不写进 `.cdb`**，也不会让文件变成「未保存」。
- 想自己加一套配色：所有颜色变量都在 `web/css/themes.css`，复制一个
  `body[data-scheme="…"]` 块改颜色，再在 `web/js/settings.js` 的 `SCHEMES` 里登记
  id、名字和三色小样，设置窗口里就会出现这张卡片。
- 表格字号变大后行高自动跟着变，虚拟滚动、单元格编辑器、二级表格都按新行高重新排布，
  不会出现「点一格跳到下一行」的错位。

工具栏用图标而不是文字（取自 Microsoft Fluent System Icons），鼠标悬停显示说明，
因此窄窗口下也能排得下；表标签（Tables 侧边栏里的表名）用深色文字配浅色底，提高可读性。

从左到右五组：表列表开关（`⊞`，展开/收起都是它）· 新增行 / 复制行 / 删除行 ·
**新增列**（表格 + 加号，插入到光标所在列右边，与表头右键 ▸ Insert Column 同一张对话框）·
复制 / 剪切 / 粘贴 / 插入粘贴 · 底色（取色、作用域、应用、清除）· 最右侧 **设置**。

### 9.2 窗口大小与位置

每个文件会记住自己上次的窗口几何（位置、大小、是否最大化），存在
`X.cdb.meta.json` 的 `windowState` 里，下次打开这个文件时自动恢复。

- 记忆的位置**只在窗口出现之前**套用一次：双击一个 `.cdb` 启动时，窗口直接出现在上次
  的位置，不会先闪到屏幕中间再跳过去。窗口一旦显示出来，再打开任何文件都不会移动它。
- 写回时机：`Ctrl+S` 保存时，以及关闭窗口/关闭文件时。
- 最大化状态下记的是**还原后的大小**，取消最大化会回到你上次调好的尺寸。
- 换了显示器、分辨率变小、窗口上次的位置已经不在桌面上了：程序会把窗口拉回可见
  区域（至少露出 120px；差得太多就重新居中），不会出现「窗口在屏幕外打不开」。
- 窗口几何只存在 `.meta.json`，`.cdb` 文件一个字节都不会变。

## 12. 常见问题

**Q：打开时提示 `Map-related column type "Layer" (type 12) is not supported`。**
本版本按需求 R1 移除了地图功能，含 12 / 14 / 15 类型列的文件无法打开。请用原版 CastleDB 打开并把该列改为普通类型。

**Q：修改列宽/颜色后 `.cdb` 没有变脏？**
这是设计如此：显示状态存在 `.cdb.meta.json` 里并立即落盘，`.cdb` 只保存数据。

**Q：为什么第二个窗口是只读的？**
防止两个窗口互相覆盖。关闭先打开的那个窗口即可解锁。

**Q：`.cdb.meta.json` 损坏了怎么办？**
程序会自动把它改名为 `.cdb.meta.json.bad` 并重建，只丢失列宽和颜色，数据不受影响。

**Q：能不能用 Ctrl 选中不连续的几块？**
不支持（需求 Q12.2）。选区始终是矩形。

**Q：撤销后光标会跳回第一格吗？**
不会。每个命令都记录执行前后的光标位置，撤销会回到操作前的位置（需求 R2）。
