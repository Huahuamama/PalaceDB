## 1. 目标与硬约束

来自需求文档的不可协商项：

1. **C# 实现**，模块职责清晰，禁止单类堆砌、禁止演示级 UI。
2. **JSON 字节级友好**：键序、Tab 缩进、LF、无 BOM、无尾随换行必须与原版一致。
3. **JSON 与元文件彻底分离**：列宽/颜色/窗口状态绝不写入 `.cdb`。
4. **地图功能全删**，含 12/14/15 三种类型。
5. **多窗口隔离**：每文件独立编辑状态、独立撤销栈。
6. **光标随命令恢复**，不得回到 (0,0)。
7. **保存原子化**，失败不破坏原文件。
8. **全英文**：UI 文案、类名、变量、注释、提交信息。

## 2. 前端宿主方案对比

| 方案 | 做法 | 优点 | 缺点 | 结论 |
| --- | --- | --- | --- | --- |
| **A. WebView2 嵌入** | WPF 窗口内放 `WebView2` 控件，`postMessage` 双向通信 | 原生窗口、无端口、进程内零网络开销、可开 DevTools、可直接读磁盘 `web/` 目录热改 | 依赖 WebView2 Runtime（本机已装） | ✅ **采用** |
| B. 本地 HTTP + 浏览器 | Kestrel 监听 `127.0.0.1:随机端口`，系统浏览器打开 | 开发调试方便、天然跨平台 | 多标签而非多窗口、有端口与安全面、文件对话框需绕行 | 仅作调试备选 |
| C. Avalonia/WPF 自绘 | 放弃 HTML，纯 XAML 绘制表格 | 无外部依赖 | 与"HTML5 前端"要求冲突；自绘虚拟化表格工作量翻倍 | 排除 |

### 2.1 WebView2 具体接法

```csharp
// 每个文档窗口一个 WebView2
await webView.EnsureCoreWebView2Async(env);

// 把磁盘目录映射为虚拟主机，避免 file:// 下 ES Module 的 CORS 限制
webView.CoreWebView2.SetVirtualHostNameToFolderMapping(
    "palacedb.local", wwwRootPath, CoreWebView2HostResourceAccessKind.DenyCors);

webView.CoreWebView2.WebMessageReceived += OnMessage;   // JS → C#
webView.CoreWebView2.PostWebMessageAsJson(json);        // C# → JS

webView.Source = new Uri("https://palacedb.local/index.html");
```

- **热改生效**：前端资源从源码目录 `web/` 直接读取（Debug 模式），改 JS 后 F5 刷新即可，无需重启。
- **Release 打包**：`web/**` 作为 `Content`（`CopyToOutputDirectory=PreserveNewest`）复制到输出目录，同样走虚拟主机映射。
- **DevTools**：Debug 下 `F12` 打开；Release 下可通过 `--devtools` 启动参数开启，便于线上排障。

## 5. 数据模型（C#）

### 5.1 值类型：`CdbValue`

为保住**键顺序**与**精确数字格式**，不使用 `object`/`Dictionary`，自定义不可变联合：

```csharp
public abstract record CdbValue
{
    public sealed record Null : CdbValue;
    public sealed record Bool(bool Value) : CdbValue;
    public sealed record Number(double Value, bool IsInteger) : CdbValue;
    public sealed record Str(string Value) : CdbValue;
    public sealed record Arr(List<CdbValue> Items) : CdbValue;
    public sealed record Obj(CdbObject Value) : CdbValue;
}

/// <summary>Insertion-ordered string→value map.</summary>
public sealed class CdbObject
{
    private readonly List<string> _order = new();
    private readonly Dictionary<string, CdbValue> _map = new(StringComparer.Ordinal);

    public IReadOnlyList<string> Keys => _order;
    public CdbValue? Get(string key);
    public void Set(string key, CdbValue value);   // 新键追加到末尾，已有键原位替换
    public bool Remove(string key);
}
```

> `IsInteger` 保留 `3` 与 `3.0` 的区别：Haxe 对 Int 列写 `3`、Float 列写 `3`（`3.0` 也输出 `3`），但对超大整数与 `1e21` 之类需要区分。保留该标志可精确复现。

### 5.2 列类型：`ColumnType` 层级

Haxe 的 `enum ColumnType` 直接映射为抽象 record 层级，模式匹配写法几乎一致：

```csharp
public abstract record ColumnType
{
    public sealed record Id : ColumnType;                                   // 0
    public sealed record Text : ColumnType;                                 // 1
    public sealed record Bool : ColumnType;                                 // 2
    public sealed record Int : ColumnType;                                  // 3
    public sealed record Float : ColumnType;                                // 4
    public sealed record Enum(IReadOnlyList<string> Values) : ColumnType;   // 5
    public sealed record Ref(string Sheet) : ColumnType;                    // 6
    public sealed record Image : ColumnType;                                // 7  (R9: 存路径)
    public sealed record List : ColumnType;                                 // 8
    public sealed record Custom(string TypeName) : ColumnType;              // 9
    public sealed record Flags(IReadOnlyList<string> Values) : ColumnType;  // 10
    public sealed record Color : ColumnType;                                // 11
    public sealed record File : ColumnType;                                 // 13
    public sealed record Dynamic : ColumnType;                              // 16
    public sealed record Properties : ColumnType;                           // 17
    public sealed record Gradient : ColumnType;                             // 18
    public sealed record Curve : ColumnType;                                // 19
    public sealed record Guid : ColumnType;                                 // 20
    public sealed record Polymorph : ColumnType;                            // 21
    public sealed record Formula : ColumnType;                              // 22
    // 12 Layer / 14 TilePos / 15 TileLayer 已按 R1 删除
}
```

**保留原版 type id**：序列化仍用 `0..22`，删除的三个 id 在读取时直接报错（见 §7.4）。

### 5.3 结构类型

```csharp
public sealed class Database
{
    public List<SheetData> Sheets { get; }
    public List<CustomType> CustomTypes { get; }
    public bool Compress { get; set; }          // 透传，不提供 UI
}

public sealed class SheetData
{
    public string Name;
    public List<Column> Columns;
    public List<CdbObject> Lines;
    public List<Separator> Separators;          // { Index, Title }
    public SheetProps Props;
}

public sealed class Column
{
    public string Name;
    public ColumnType Type;
    public bool Optional;                       // opt
    public DisplayType Display;                 // Default | Percent
    public ColumnKind Kind;                     // None | Localizable | Script | Hidden | TypeKind
    public int? Scope;
    public string? Documentation;
    public CdbValue? Editor;                    // 透传
    public CdbValue? DefaultValue;
    public bool Shared;
    public string? StructRef;
    public bool EnumAsString;                   // enumStr
}
```

### 5.4 索引与引用

`SheetIndex` 在 `SheetData` 之上构建（等价于原版 `Sheet.sync()`）：

- `ById : Dictionary<string, CdbObject>`（首个 ID 列）
- `All : List<SheetIndexEntry>`（按显示名排序）
- `DuplicateIds : HashSet<string>`
- `Children`：`表名@列名` 子表解析（List/Properties/Polymorph）

**只在结构变更时重建**（增删行、改 ID、改列），不随单元格值变化全量重建。

## 6. JSON 序列化方案

### 6.1 读取

```csharp
using var doc = JsonDocument.Parse(utf8Bytes, new JsonDocumentOptions {
    AllowTrailingCommas = false,
    CommentHandling = JsonCommentHandling.Skip
});
var root = CdbReader.Read(doc.RootElement);   // → CdbObject，保持键序
```

- 用 `JsonDocument` 而非 `JsonNode`：前者能拿到 `GetRawText()`，便于对数字做精确判定。
- 读取后立即做**类型解析**：`typeStr` → `ColumnType`；`separators` 三种形式归一。

### 6.2 写入（关键）

```csharp
public static string Write(Database db)
{
    var sb = new StringBuilder(1 << 20);
    WriteObject(sb, ToCdbObject(db), depth: 0);
    return sb.ToString();   // 无尾随换行
}
```

规则（全部有对应单测）：

| 规则 | 实现 |
| --- | --- |
| 缩进 | 每层 1 个 `\t` |
| 换行 | `\n` |
| 空对象 | `{}`（不换行） |
| 空数组 | `[]`（不换行） |
| 键值分隔 | `"key": value`（冒号后 1 空格） |
| 元素分隔 | `,\n` |
| 字符串转义 | `"` `\` `\b \f \n \r \t` 与控制字符 → `\uXXXX`；**中文原样输出**（UTF-8） |
| 整数 | `value.ToString(CultureInfo.InvariantCulture)` |
| 浮点 | `value.ToString("R", InvariantCulture)`；`1.0` → `1`；`NaN`/`Infinity` 拒绝 |
| null | 字面量 `null` |
| 编码 | UTF-8 **无 BOM** |
| 尾随换行 | **不写** |

### 6.3 键顺序策略

**读入什么顺序，就写什么顺序**。新增字段追加到对象末尾。

因此 `CdbObject` 必须保序；`CdbWriter` 按 `Keys` 顺序输出。这样"打开→保存"对未改动文件可做到**字节一致**（除数字格式归一化外），git diff 最小。

### 6.4 兼容性验收

| 用例 | 判据 |
| --- | --- |
| `TestData1.cdb` 打开→保存 | 与原文件**字节一致** |
| `TestData2.cdb` 打开→保存 | 与原文件**字节一致** |
| 改一个单元格后保存 | diff 只包含该行该字段 |
| 原版 1.5 打开新软件保存的文件 | 无报错，数据一致 |
| 新软件打开 1.5 保存的文件 | 无报错，数据一致 |

> 若某文件因数字格式（如 `1e21`）无法字节一致，则降级为"语义等价 + 键序一致"，并在测试报告中标注。

## 7. JSON 与元文件的关系（重点）

### 7.1 职责边界

```
X.cdb                    X.cdb.meta.json
─────────────────        ─────────────────────────────
数据（唯一真相）          呈现状态（可丢弃、可重建）
- sheets                 - 列宽
- columns                - 行/列/单元格背景色
- lines                  - 窗口尺寸位置
- separators             - 每表光标位置（可选）
- props                  - 列 id ↔ 名称映射
- customTypes            - 展开状态（可选）
- compress
─────────────────        ─────────────────────────────
原版可读                 原版忽略（未知扩展名）
游戏引擎可读             丢失后软件仍完全可用
```

**铁律**：

1. 元文件里的任何东西**都不得**写进 `.cdb`。
2. `.cdb` 里任何数据的语义**都不得**依赖元文件。
3. 删掉元文件 → 软件正常打开，只是回到默认列宽/无颜色。

### 7.2 关联键

| 元数据 | 主键 | 说明 |
| --- | --- | --- |
| 表 | `tableId`（uuid，首次见到该表时生成） | 表改名不变；表删除后记录保留为孤儿 |
| 列 | `columnId`（uuid） | 列改名/移动不变；靠 `name` 快照做外部改名回退匹配 |
| 行 | 有 `TId` 用 ID 值；无 `TId` 用行索引 | 索引随插入/删除由软件平移 |
| 单元格 | `(rowKey, columnId)` | — |

`tableId` / `columnId` **不写入 `.cdb`**，只存在于元文件。首次打开旧文件时按名称批量生成。

### 7.3 生命周期

| 事件 | `.cdb` | `.meta.json` |
| --- | --- | --- |
| 打开 | 读 | 读；不存在则内存初始化，**不落盘** |
| 编辑单元格 | 内存 | 不变 |
| 拖列宽 / 设颜色 | 不变 | 内存 + 节流 300ms 落盘 |
| Ctrl+S | 原子写 | 若脏则写 |
| 另存为 | 写新文件 | 复制并改 `fileId` |
| 关闭（脏） | 提示保存 | 若脏则写 |
| 删除 | 用户操作 | 提示是否一并删除 |

### 7.4 异常与边界

| 场景 | 行为 |
| --- | --- |
| 元文件损坏 | 重命名为 `X.cdb.meta.bad`，用默认值继续，状态栏提示 |
| 元文件版本更高 | 只读使用（不写），提示 "Metadata created by a newer version" |
| 元文件版本更低 | `MetaMigrator` 链式升级后写回 |
| 主文件保存失败 | 元文件不写（避免状态超前于数据） |
| 主文件外部被改 | 重载后按 ID 重新绑定元数据；无法匹配的保留为孤儿 |
| 表/列被删除 | 元数据记录保留 30 天（软删除），避免误删后无法恢复 |
| 同一文件多窗口 | 进程内共享同一 `MetaStore` 实例，天然无冲突 |
| 跨进程同文件 | 文件锁 + 时间戳比较；后写者合并（只合并样式，不合并数据） |

## 8. 文档会话与命令栈

### 8.1 会话

一个窗口持有一个 `DatabaseDocument`（`Core/Document/DatabaseDocument.cs`），它把数据模型、
元数据、撤销栈和脏状态绑在一起：

```csharp
public sealed class DatabaseDocument : IDisposable
{
    public string Path { get; }              // 文件路径；未命名文档指向数据目录下的临时名
    public Database Database { get; }
    public MetaStore Meta { get; }           // X.cdb.meta.json
    public CommandStack Commands { get; }
    public DatabaseIndex Index { get; }
    public bool IsDirty { get; }             // 数据与上次保存不同
    public bool IsReadOnly { get; }          // 别的窗口在写 / 文件只读 / 元数据要求只读
    public bool IsUntitled { get; }          // File ▸ New 出来的、还没有文件

    public static DatabaseDocument Open(string path);                 // 普通打开
    public static DatabaseDocument OpenMerged(string path, string mergedText); // F16
    public static DatabaseDocument CreateUntitled(string scratchPath);         // F01
    public bool Save();  public void SaveAs(string newPath);  public bool WriteBackup();
}
```

**三种打开方式**的差别只体现在「有没有文件」和「是否已落盘」：

| 方式 | `Path` | 初始脏状态 | 首次保存 |
| --- | --- | --- | --- |
| `Open` | 真实文件 | 干净 | 直接写回原文件 |
| `OpenMerged` | 真实文件 | **脏**（内容只在内存里） | 写回原文件，成功后删除 `.mine` / `.r<N>` |
| `CreateUntitled` | 数据目录下的临时名，**不落盘** | **脏** | 必须走 `SaveAs` 选位置；`Save()` 直接抛错 |

未命名文档借用临时路径只是为了让元数据有地方落，它同时被排除在自动备份和外部改动检测之外，
否则会在数据目录里留下永远没人打开、也永远"被外部修改"的垃圾文件。

脏状态用「撤销栈栈顶命令引用是否等于上次保存时的栈顶」判断，而不是全量比对 JSON：
一次编辑后 `Ctrl+Z` 回到保存点，文档会自动变回"干净"。

### 8.5 表格模板（R14）

模板让几张表的列定义**保持同一份**。它不是一种新的数据结构，而是「一份列定义 + 一张表名单」，
放在元数据里（`templates`，见 05 §2.5），因为它是编辑器的约定，游戏端不需要知道。

**列定义脱离表存在**。`ColumnSpec`（Core/Model）是一列的完整定义快照：`name`、规范化的
`typeStr`、`optional`、`display`、`kind`、`defaultValue`、`enumStr`、`scope`、
`documentation`、`shared`，以及 List / Properties 的字段表。`ColumnSpec.From(column, sheet)`
从真实列取快照，`ToRaw()` 把它写成 `.cdb` 里的列对象。`SameType` / `SameDefinition` 做结构比较
（默认值用 `CdbWriter.WriteValue` 比，所以结构化默认值也能比）。

**模板定义是派生态，不进撤销历史**。定义不单独编辑，而是从「刚被编辑的那张成员表」重写
（`MetaStore.RefreshTemplate`）。打开文件时 `RefreshTemplates` 只在所有成员表一致时刷新，
不一致就把存着的定义当基准，并在界面上把那张表标成 out of sync。这样 `Ctrl+Z` 撤销列改动时
模板自然回到旧值，不需要为它再记一条命令。模板本身（新建 / 改名 / 删除）不进撤销栈——
它可能被别的表用着；但「这张表开始 / 停止跟随」是可撤销的 `TemplateLinkCommand`。

**列编辑走语义操作**。所有列编辑被改写为 `ColumnOp`（按**列名**记录，不是下标）：
`RenameColumnOp`、`RetypeColumnOp`、`OptionsColumnOp`、`DeleteColumnOp`、`InsertColumnOp`、
`MoveColumnOp`。`ColumnOps.Build(sheet, op, database, fillInsertedRows)` 是唯一知道安全规则的地方
（最后一列不能删、一个 ID 列、List 列带着它的隐藏子表一起改）。

**镜像就是一个复合命令**。`TemplateService.BuildMirrored` 把同一批 `ColumnOp` 在每张兄弟表上重放，
合成一个 `CompositeCommand`：一次撤销把所有表一起还原。命令里的目标顺序与插入下标在 `Execute()`
时才解析（`ColumnReorderCommand` / `ColumnInsertCommand`），因为一批插入会在执行前就被构建出来。

**套用前的审计**。`TemplateService.Audit(sheet, template)` 只放行两种差异：缺列（补空列，
**不给已有行写默认值**）和顺序不同（重排）。多出的列、同名列类型或字段不一致都算冲突，
报告出来后什么都不改。唯一能靠改模板解决的冲突（多出的列）在报告里给出一键扩展
（`extendTemplate`：以这张表为新定义，其余成员补列）。

**影响先量后问**。删除列、改类型这两个破坏性操作，由宿主**数**出代价：
`MeasureDelete` 数每张成员表里该列的非空值；`MeasureRetype` 对每个值真的跑一次
`ValueConverter.Convert` 再和原值比（Enum 文本能对上标签的不算丢失）。有代价时宿主不执行，
而是回一条 `columnImpact`（每张表的行数、值数、总数，外加一份带 `confirmed: true` 的
`retry` 载荷）；界面只负责显示并把 `retry` 原样发回，所以对话框显示的数字和实际执行的
永远是同一份测量。

### 8.6 公共类型与自增编号（R15）

**公共类型不是新数据结构，而是「一份取值表 + 一张列名单」**，放在元数据里
（`publicTypes`，见 05 §2.6）。每个绑定列在 `.cdb` 里写**完全相同**的 `typeStr`，
所以游戏端读到的就是普通 Enum / Flags，不需要理解这个概念；绑定关系只在 side-car 里。

**一条命令改所有列**。`PublicTypeService.BuildUpdate` 把「改定义」翻译成一个命令：
先给每个绑定列准备新的 `typeStr`，再按重映射规则改写存量值，最后合成一步撤销。
重映射的规则是保守的——按名字跟、列表长度不变才保留位置、值被删则回落到第一项
（详见 07 §9.1）。

**打开时自检**。`RepairPublicTypes()` 在 `AdoptDocument` 之后比对定义与绑定列，
被外部工具改歪的列按定义纠正，作为一步可撤销的命令并提示，避免「静默不一致」。

**List / Properties 的字段也能绑**。字段是隐藏子表（`Items@tags`）的列，所以它就是「另一张表的
一列」，绑定同样记在 side-car 的 `tables['Items@tags'].columns` 里，`.cdb` 里写的也是同一份
`typeStr`。两处与普通列不同，都在宿主里处理：

- **取值不在自己身上**。子表没有行，字段的值在父列每条记录的对应键里，所以
  `PublicTypeValuesCommand` 用 `SlotsOf()` 把「记录 + 字段名」列出来，`Before`/`After` 针对这些
  槽位准备，`Write` 写回记录而不是 `sheet.Lines`（否则改定义只会改列定义、记录里的索引不动）。
- **没有结构变更也要落盘**。只换绑定时 `SubColumnsCommand` 是 no-op，`EditColumn` 因此会走
  「无命令」分支；这条分支要额外调 `RememberSubFieldPublicTypes`，否则界面显示已绑定、
  side-car 里却没有。

**自增列是普通 Int 列 + 一个标记**（`autoIncrement`），不是新列类型，`.cdb` 里看到的仍是 `"3"`。
编号发生在四个入口：新列补值（1..N）、新行（`AutoNumber.Next`）、复制行（顺序递增）、
粘贴新增行（`AssignAutoNumbers`）。

**Guid 逐行生成**。`ColumnInsertCommand` 对 Guid 与自增列走 `perRow` 分支，
不再「算一个默认值填所有行」——这正是此前 Guid「没做完」的地方。

### 8.7 视图状态：折叠行分组与隐藏列（R16）

两者都是「怎么看这张表」，所以都走同一条路线：**前端即时生效 → 宿主写 side-car → 重发
`document` 把状态带回来**，`.cdb` 与撤销栈都不参与。

- **行分组**：分组的定义与 `group` 字段完全一致（一条带标题的分隔线开一组，到下一个带标题
  分隔线为止），所以前端只需要分隔线的标题。`Grid.rebuildVisibility()` 把「收起的标题」
  展开成每行一个隐藏标记，再用一个前缀和 `hiddenPrefix[i]` 让 `topOf(i)` 保持 O(1)：
  `(i - hiddenPrefix[i]) * ROW_HEIGHT + …`。收起的组标题条仍然占一行（`separatorStrips` 里
  保留它、`separatorShift` 从 `S+1` 起算），否则整组连入口一起消失。
- **列**：不删列、不改索引，只把宽度记 0 并加 `hidden` 类。行数据按位置存（`data.cells[colIndex]`），
  索引一动就全串位；宽度归零让所有横向偏移计算原样可用。
- 光标是唯一需要主动处理的东西：`snapRow` / `snapCol` 把它挪到最近一个还看得见的位置，
  折叠时若光标落在组内则移到组后第一行。
- 分隔条画不画**按像素位置判断**：`separatorTop(i)` 与窗口的 `topOf(first)` / `topOf(last)`
  比较。收起组的标题条画在 `topOf(首行)`，它的行号可能远在窗口上方而像素正好在窗口里，
  按行号筛会把它筛掉（症状是「折叠后分割线不见了」）。

### 8.8 侧栏：三个标签页（R16）

表列表、公共类型、列清单原来上下堆在同一列里，三份都只剩几行高。现在 `#sidebarTabs` 是
`role="tablist"` 的三个 `.sidebar-tab`，下面三个 `.sidebar-panel`（`data-panel` 对应
`tables` / `types` / `columns`），**永远只有一个没有 `hidden`**。

- `applySidebarTab(name, {persist})` 是唯一的开关：写 `aria-selected`、切 `panel.hidden`、
  记 `localStorage['palacedb.sidebar.tab']`，并顺手 `renderTableList()`。
- 三个列表在**隐藏时也照常更新**（`document` 回来就重画），所以切标签只是「显示」，没有重建。
- `+` 只有一个（`#sidebarAdd`），行为跟着当前标签走：Tables 建表、Types 建公共类型、
  Columns 无事可做。Columns 页用 `.off`（`visibility:hidden`）而不是 `hidden` 藏它——
  一旦把它从布局里拿掉，三个 `flex:1` 的标签会变宽，整个标签栏跟着跳。
- 侧栏收起仍是 `.sidebar.collapsed { display: none }`，标签栏随之消失，由钉在左上角的
  `⊞` 拉回来。

## 10. 表格渲染与编辑（前端）

### 10.1 虚拟化

```
.grid 是两列网格：--gutter-width | 1fr
┌────────┬──────────────────────────────────────────────┐
│ 角落   │ 表头（overflow: hidden，横向 transform 跟随） │
├────────┼──────────────────────────────────────────────┤
│ 行号列 │ 行容器（position: relative，高 = 行数 × 行高）│
│ (不滚动)│   └ 可视行（绝对定位，top = index × 行高）   │
└────────┴──────────────────────────────────────────────┘
```

- 基准行高来自 CSS 变量 `--row-height`（默认字号下 38px），JS 用 `refreshMetrics()` 从样式表读取，
  两边不会漂移；字号设置变化时重新读取并重排（见 §12.1）。
- 可视区外上下各预渲染 6 行；行 DOM 每次渲染重建，节点数与可视行数同阶。
- 行号列放在**滚动容器之外**：横向滚动时行号不会被带走，也不需要 sticky 或偏移换算；
  它的数字用与行相同的窗口和 `top = topOf(index) − scrollTop` 绘制。
- 列宽直接写在每个单元格的 `style.width`，表头与单元格用同一份数据。

#### 10.1.1 行高不固定（长文本自动换行）

一个值换行之后，行必须长高到能放下它，否则表格会显示半截文字。但虚拟化要求
"任意一行的 y 坐标可算"，两者本来是矛盾的，这里用"**只记住变高的行**"来调和：

```js
rowHeights: Map<rowIndex, height>   // 只存 > 基准行高的行
topOf(i) = i × 基准行高 + Σ(前面那些变高的行的增量) + 展开面板高度
```

- 增量之和用**排序后的前缀和**（`heightRows` / `heightPrefix`）加二分查找，O(log k)；
  `k` 是变高的行数。**没有变高的行时（绝大多数表格），这段代码完全不参与**，
  `topOf` 退化成原来的 `i × 行高`，性能与改动前一致。
- 测量在渲染后进行：可视行插入 DOM → 一次性读它们的 `.cell-value` 高度（**先读后写**，
  只触发一次布局）→ 需要变高的行记进 map → 重排可视行、行号、spacer 和展开面板。
- 测的是**内容元素**而不是行本身，所以行高不会反过来影响测量，不会来回抖动。
- 可视区用 `rowIndexAt(y)` 二分查找首行，再往下累加直到越过视口；不再用
  `floor(scrollTop / 行高)`，因为行高不一致时那个估算会跳行。
- 失效时机：换表、换字号、列宽变化、编辑某行、`invalidate`。都只清缓存，重测即可。
- 上限：`.cell-value` 的 `max-height` 约二十行，防止一个离谱的值把整张表挤走；
  完整文本仍在 tooltip 和编辑器里。

前端不持有全量数据：

### 10.3 单元格编辑器

| 类型 | 控件 | 提交时机 |
| --- | --- | --- |
| Text | `<textarea>` 自动增高 | 失焦 / Ctrl+Enter |
| Int / Float | `<input type=text>` | 失焦 / Enter |
| Bool | 单击切换 | 立即 |
| Enum | `<select>` | change |
| Flags | 复选框浮层 | 关闭浮层 |
| Ref | 可搜索下拉（自研，支持图标） | 选中 |
| Color | 色板 + 取色器 | 选中 |
| Image | 缩略图 + 拖放/选择 | 选中文件 |
| File | 文件名 + 预览 + open | 选中文件 |
| List / Properties | 行下展开的**二级 Grid**（同一套 `Grid` + `CellEditor`，`store` 写回单元格） | 每次编辑后 250ms 防抖；收起 / 保存 / 撤销前 flush |
| Custom / Dynamic / Formula | 文本框（按 JSON 文本编辑） | 失焦 / Enter |
| Guid | 文本框（13 位编码） | 失焦 / Enter |
| Gradient / Curve / Polymorph | 文本框（JSON 文本，原样透传） | 失焦 / Enter |

二级表格有两条容易漏掉的约定：

- **展开态占位**：`Grid.buildRow` 画单元格时先查 `panels`，命中就只画 `…` 并加 `.expanded`，
  不再画原值；收起面板会触发一次 `render()`，原值自己回来，不需要额外的还原逻辑。
- **字段编辑要落到数据上**：`Fields...` 复用同一张 `editColumn` 表单，宿主在同一个
  `CompositeCommand` 里执行 `SubColumnsCommand`。它按字段名对账（表单带 `id`，即字段的旧名），
  重建隐藏子表的 `columns`，并把每个单元格里已经存好的记录按新字段重排：改名搬值、删字段丢值、
  新字段补 `TypeDefaults`、改类型走 `ValueConverter`。字段列表没变时是 no-op，不产生撤销步。
  列改名时子表名（`Table@Column`）也跟着改，否则字段会从列上「消失」。

### 10.4 校验结果由宿主回答

状态栏的「第一个错误」不是前端扫出来的。前端只持有可视行，扫出来的错误会随滚动出现和
消失，所以由宿主回答：

- `PalaceDB.Core.Editing.SheetValidator.FirstIssue(sheet, db, index)` 顺序遍历整张表，
  只检查**可能出错的两类列**——ID 列（空 / 重复）与引用列（空 / 目标行或目标表不存在），
  不格式化每个单元格，十万行也在毫秒级返回。
- 宿主在 `document` 与 `rowUpdated` 之后各发一条 `firstIssue` 事件
  （`{sheet, row, column, detail}`，无错误时 `row` 为 null）。
- 前端 `refreshIssue()` 只负责把它写进状态栏，形如
  `EventCard · Row 1: Duplicate identifier 'vocational'`。

### 10.5 键盘路由

全局 `keydown` 监听 → `GridController.handleKey()`，与输入框内编辑态互斥（`isEditing` 标志）。快捷键表见需求文档 §2.G。

- 颜色格式 `#RRGGBB`（不透明）或 `#AARRGGBB`。
- 深色背景自动切换文字色（亮度阈值 0.55）。
- 样式变更即时下发前端（全量样式数据量小，<100KB，可整包推送）。

### 12.1 外观设置：字号与配色

界面上所有颜色和尺寸都走 CSS 自定义属性，因此「换配色」「改字号」只是改一组变量的值，
不需要任何组件知道这件事：

| 变量 | 来源 | 影响 |
| --- | --- | --- |
| `--font-size` / `--font-size-small` | 界面字体大小（12–20px） | 菜单、工具栏、对话框、状态栏 |
| `--grid-font-size` | 表格文本大小（10–20px） | 表头、单元格、行号、单元格编辑器 |
| `--row-height` / `--head-height` / `--gutter-width` | 由表格字号推导（`round(字号 × 2.72)` 等） | 行高、表头高、行号列宽 |
| 其余 `--bg/--text/--accent/...` | 配色方案 | 整套界面 |

**关键点：行高是推导出来的，不是常量。** 网格用它把「第几行」换算成像素位置
（`topOf(index) = index × ROW_HEIGHT + 变高增量 + 展开面板高度`），所以改字号时必须同时刷新
`grid.js` 里缓存的 `ROW_HEIGHT`（`refreshMetrics()`），同时**清掉测好的行高**
（`clearRowHeights()`，字号变了就会换行不同），并让已经展开的二级表格重新
`measure()`。否则行还停在旧高度，点一格就会落到相邻行——这正是早期「光标错位」的成因。

配色方案通过 `<body data-scheme="...">` 切换，深色系同时带 `theme-dark` 类：
`theme-dark` 提供整套深色变量，`data-scheme` 只在上面覆写该方案不同的部分
（Graphite 的中性灰、Deep Sea 的深蓝），因此新增一套配色只需要十几行变量。

**配色集中在一个文件里。** 所有颜色变量都在 `web/css/themes.css`：`:root` 是浅色系，
`body.theme-dark` 是深色系，每个具名方案是一个 `body[data-scheme="…"]` 块，只覆写
自己与所属色系不同的部分。`app.css` 一个颜色都不定义，只读变量，所以换肤不会碰到版式。
加一套配色 = 复制一个块改颜色 + 在 `js/settings.js` 的 `SCHEMES` 里登记 id、名字和三色小样。

**字号是全局的，配色是随文件的。** 两者存储位置不同，原因也不同：

| 项 | 存储 | 理由 |
| --- | --- | --- |
| 界面字体大小 / 表格文本大小 | 本地存储 `palacedb.settings` | 描述「这台机器上的人」，换文件不该变 |
| 配色方案 | 文件的 `X.cdb.meta.json` → `appearance.scheme` | 描述「这份数据」，同时开两个库时靠颜色区分 |
| 没有配色的文件 | 回落到本地存储里的偏好 | 新建的库直接沿用上次的选择 |

前端改配色时同时写两处：本地存储（作为新文件的默认值）和宿主（`setFileScheme`，
落到当前文件的 side-car）。`MetaStore.SetScheme` 在值没变时返回 false，因此只是打开
设置窗口看一眼再关掉，不会写盘。

## 13. 持久化与异常恢复

### 13.1 原子写入

```csharp
public static void WriteAtomic(string path, string content)
{
    var dir = Path.GetDirectoryName(path)!;
    var tmp = Path.Combine(dir, "." + Path.GetFileName(path) + ".tmp");
    File.WriteAllText(tmp, content, new UTF8Encoding(false));   // 无 BOM
    if (File.Exists(path))
        File.Replace(tmp, path, null, ignoreMetadataErrors: true);
    else
        File.Move(tmp, path);
}
```

- 同卷替换，`File.Replace` 在 NTFS 上是原子的。
- 失败时原文件不变；临时文件清理。

### 13.2 自动备份（C1）

| 项 | 规则 |
| --- | --- |
| 触发 | 定时器每 60s 检查；`IsDirty && now - lastBackup >= 5min` → 备份 |
| 文件 | `X.cdb.bak`（单份，覆盖） |
| 内容 | 当前内存状态（含未保存修改） |
| 清理 | 保存成功后删除 |
| 恢复 | 启动时若 `.bak` 的 mtime > `.cdb` 的 mtime → 提示 `Recover unsaved changes?` |

### 13.3 锁

- 路径：`%LOCALAPPDATA%\PalaceDB\locks\<sha1(path)>.lock`
- 方式：`FileStream(..., FileShare.None)`，进程退出自动释放
- 用途：跨进程同文件检测（不污染数据目录）

### 13.4 异常兜底

| 异常 | 处理 |
| --- | --- |
| 文件被占用 | 重试 3 次（间隔 300ms），仍失败 → 提示并保留内存状态 |
| 磁盘满 | 捕获 `IOException`，提示，**不删除**临时文件前先确认原文件完好 |
| 反序列化失败 | 保留原文件路径，展示错误位置（行/列），进入只读空白态 |
| 前端崩溃 | 捕获 `ProcessFailed`，重建 WebView 并重放当前状态 |
| 未处理异常 | 全局 handler 记录日志 + 提示，不静默退出 |

## 14. 进程内通信协议

### 14.1 消息格式

```jsonc
// 请求（JS → C#）
{ "id": 42, "method": "cell.set", "params": { "sheet": "EventCard", "row": "vocational", "column": "c7d8", "value": "x" } }

// 成功
{ "id": 42, "result": { "ok": true, "patch": { ... } } }

// 失败
{ "id": 42, "error": { "code": "TYPE_MISMATCH", "message": "Cannot convert Text to Int" } }

// 事件（C# → JS，无 id）
{ "event": "document.dirtyChanged", "payload": { "dirty": true } }
```

### 14.2 方法清单（首版）

| 域 | 方法 |
| --- | --- |
| 文档 | `doc.getState` `doc.save` `doc.saveAs` `doc.reload` `doc.close` |
| 表 | `sheet.list` `sheet.getLayout` `sheet.create` `sheet.rename` `sheet.delete` `sheet.move` `sheet.setProps` |
| 列 | `column.create` `column.update` `column.delete` `column.move` `column.convert` |
| 行 | `rows.get` `row.insert` `row.delete` `row.move` `rows.copy` `rows.paste` `rows.insertPaste` |
| 单元格 | `cell.set` `cells.bulkSet` `cells.clear` `cells.copy` `cells.paste` |
| 历史 | `undo` `redo` `history.getState` |
| 元数据 | `meta.setColumnWidth` `meta.setStyle` `meta.clearStyle` `meta.setWindowState` |
| 类型 | `types.get` `types.update` |
| 系统 | `system.openFile` `system.chooseFile` `system.chooseSavePath` `system.showMessage` |

### 14.3 补丁格式

```jsonc
{
  "rowsChanged": [ { "key": "vocational", "cells": { "c7d8": { "v": "x", "text": "x", "state": "ok" } } } ],
  "rowsInserted": [ { "index": 12, "key": "new_row" } ],
  "rowsDeleted": [ "old_row" ],
  "layoutChanged": false,
  "dirty": true
}
```

前端按补丁增量更新 DOM，不重建表格。
