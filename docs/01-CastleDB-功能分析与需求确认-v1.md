## 1. 阶段 1 研究结论

### 1.1 版本与来源

| 项目 | 结论 |
| --- | --- |
| 上游仓库 | `github.com/ncannasse/castle`（即 `castle-master`） |
| 官方最新发行版 | **CastleDB 1.5**（2015-10），即 `castledb/cdb.exe` |
| 上游状态 | README 明确：**编辑器已重写并并入 HIDE（heaps.io）**，本仓库编辑器为 legacy，`cdb` 运行库仍在维护 |
| 源码版本 | 比 1.5 二进制**更新**，属 1.5 之后的开发分支快照（含 TProperties/TPolymorph/TFormula 等新类型） |
| 结论 | 不存在"更新的独立 CastleDB 编辑器"。**功能基准 = castle-master 源码 + 官方文档（www/index.html）** |

### 1.2 源码与随附二进制的差异

对比 `castledb/castle.js`（1.5 构建产物）与 `castle-master/src`：

| 能力 | 1.5 二进制 | castle-master 源码 | 本项目 |
| --- | --- | --- | --- |
| 列类型 | 0–16 + Layer/TileLayer/TilePos | **0–22** | 采用 0–22（再减去地图 3 类） |
| `structRef` 结构共享 | 无 | 有 | 采用 |
| 文本单元格 | 多行 `textarea` | 单行 `input` | **多行（C6）** |
| Ctrl+F 快速过滤 | 无 | 有 | 采用 |
| Recent Files | 无 | 有 | 采用 |
| Export Localized texts | 无 | 有 | 采用 |
| Edit Types | 入口被编译期裁剪 | 有 | 采用 |
| Localizable / Properties | 无 | 有 | 采用 |
| 菜单快捷键显示 | 无 | 有 | 采用 |

> 新软件按超集实现，既能打开你现有的两个文件，也能打开新版源码产生的文件。

### 1.4 数据模型（JSON）

```jsonc
{
  "sheets": [{
    "name": "EventCard",
    "columns": [ { "typeStr": "0", "name": "Id" }, { "typeStr": "1", "name": "Title", "display": null } ],
    "lines": [ { "Id": "vocational", "Title": "职业培训", "RstValue": "money-600", "EventType": 0 } ],
    "separators": [0, 4, 9],
    "props": { "separatorTitles": ["school_offer", "..."] }
  }],
  "customTypes": [],
  "compress": false
}
```

- 列类型用 `typeStr`：`"3"`=Int，`"5:A,B,C"`=Enum，`"10:A,B"`=Flags，`"6:SheetName"`=Ref，`"9:TypeName"`=Custom。
- 行数据是**稀疏对象**：`opt` 字段无值时不写键。
- 列属性：`opt`、`display`、`kind`、`scope`、`documentation`、`editor`、`defaultValue`、`shared`、`structRef`、`enumStr`。
- 表属性：`displayColumn`、`displayIcon`、`hide`、`isProps`、`hasIndex`、`hasGroup`、`level`（删除）、`dataFiles`、`editor`。

### 1.5 文件格式（逐字节核对）

| 项 | 实测 |
| --- | --- |
| 编码 | UTF-8，**无 BOM** |
| 换行 | **LF**，非 CRLF |
| 缩进 | **Tab**，一层一个 |
| 结尾 | **无尾随换行** |
| 键顺序 | 顶层 `sheets, customTypes, compress`；表 `name, columns, lines, separators, props`；**按读入顺序保留** |
| 空值 | 显式写 `null`（如 `"display": null`） |

> 必须自研 JSON 写入器（`System.Text.Json` 会重排/丢键序，无法保证 Tab 缩进与无尾随换行）。否则每次保存产生全文件 diff，破坏原版"git 友好"这一核心卖点。这是硬性兼容要求。

### 1.6 附属文件

| 文件 | 用途 | 本项目 |
| --- | --- | --- |
| `X.cdb` | 主数据 | 保留 |
| `X.img` | TImage 的 MD5 → dataURL 映射 | **删除**（R9） |
| `X.cdb.mine` / `.rN` | git 冲突残留，启动时三方合并 | 保留（C4） |
| `%TMP%/X.cdb.lock` | 保存期临时标记（**不是真锁**） | 替换为真实锁 |
| localStorage `prefs` | 窗口位置、当前文件、当前表、最近文件 | 改为应用配置文件 |

### 1.7 保存与刷新机制（影响所有新增需求）

1. **每次修改立即落盘**：任何编辑都调用 `save()`，整库重新序列化写盘。无脏状态，无保存按钮。
2. **写入非原子**：截断 + 写，中途崩溃即损坏。
3. **撤销 = 全量快照**：内存保存最多 100 份完整 JSON（上限 300MB），Ctrl+Z 整库反序列化 + 全 UI 重建。
4. **外部修改监听**：1 秒定时器比对 mtime，一变就整库重载（撤销历史清空）。
5. **UI 全量重绘**：任何结构变化都重建整张表，无虚拟化。

## 3. 原版关键机制与已确认缺陷

### 3.1 撤销/重做 = 全量快照

```haxe
save() → { d: 整库 JSON 字符串, o: serialize(openedList) } → 压入 history（≤100 条 / ≤300MB）
Ctrl+Z → quickLoad(history.pop()) → base.load(整库反序列化) → initContent()（全 UI 重建）→ save(false)
```

**后果**：

1. 每次编辑产生完整 JSON 字符串，大库内存爆炸（10MB × 100 = 1GB）。
2. 撤销后**所有对象引用失效**，`cursor.s` 指向旧 `Sheet`；`refresh()` 检测到 `cursor.s != viewSheet`，调用 `setCursor(viewSheet, false)`，参数默认 `x=0, y=0` → **光标跳回第一列第一格**。已定位到确切路径：`Main.hx` 280–295 行（撤销）、1354 行（判断）、1959 行（默认值）。
3. 撤销后整表重绘，滚动位置丢失。

### 3.2 光标模型

- `cursor = { s:表, x:列, y:行, select:{x,y}, onchange }`，`x = -1` 表示整行。
- `sheetCursors: Map<表名, Cursor>` 实现切表记忆，但**嵌套列表游标不记忆**。
- 光标与操作历史**无关联**——这是 R3 要解决的核心。

### 3.3 剪贴板模型

- `clipboard = { text, data:Array<对象>, schema:Array<列> }`。
- 粘贴前置条件：系统剪贴板文本必须等于 `clipboard.text`，否则**静默忽略** → 无法从 Excel 粘贴。
- 只做"按列偏移覆盖"，无插入语义，无 ID 冲突处理。

### 3.4 分隔线表示不一致（上游 bug）

- 1.5：`separators: [0, 33, 39]`（整数数组）。
- 新版源码：解析后转成 `{index:n}` 对象，但 `popupLine` 里又 `insert(sepIndex, index)` 插入整数 → 类型混用，`Lambda.indexOf` 恒为 -1，"取消分隔线"可能失效。
- 本项目统一内部模型 `Separator { Index, Title }`，写盘按 C5（整数数组），解析兼容三种。

### 3.5 其他已确认问题

| 问题 | 位置 | 影响 |
| --- | --- | --- |
| 保存非原子（截断+写） | `Model.save()` | 崩溃即损坏源文件 |
| 保存失败只重试一次且无提示 | 同上 | 用户误以为已保存 |
| 外部改动 1s 后整库重载 | `checkTime()` | 编辑被打断，撤销历史清空 |
| 加载失败清空 `prefs.curFile` | `Model.load()` | 下次保存写到"无文件"状态 |
| 全表重绘 | `refresh()` | 万行级卡顿 |
| 粘贴静默失败 | `onKey` Ctrl+V | 用户无反馈 |
| `hasIndex`/`hasGroup` 写盘退化 | 新版 `Database.save()` 不写 `index`，且**删除** `group` | 与官方文档和 1.5 行为不符；本项目按 1.5 行为实现 |

## 4. 新增与变更需求分析

### 4.1 删除地图功能（R1）

**原版现状**：独立子系统（`Level.hx` 2004 行 + `lvl/*` 2080 行 + palette + tileset）。入口 3 处：新建表的 "Create Level"、表右键 "Level"、每行 "Edit" 按钮；另有 Level 标签页。

**依赖验证（已完成）**：

| 文件 | 表数 | 行数 | 用到的类型 | 地图类型列 | `props.level` | 隐藏子表 | `compress` |
| --- | --- | --- | --- | --- | --- | --- | --- |
| TestData1.cdb | 18 | 658 | 0,1,3,5,10 | **无** | 无 | 无 | false |
| TestData2.cdb | 6 | 205 | 0,1,2,3,4,5,10 | **无** | 无 | 无 | false |

**结论：两个测试文件完全不受影响 → 按决议全部删除。**

**删除清单**：

1. UI：Level 标签页、"Create Level"、"Level" 菜单、地图视图、调色板、瓦片选择对话框。
2. 类型：`TLayer(12)`、`TTilePos(14)`、`TTileLayer(15)`。
3. 数据逻辑：`props.level`、`changeLineOrder`、`cleanLayers`、`updateValue` 的 width/height 分支、`getLines` 的 `tileProps` 特判。
4. 编码：LZ4 压缩（`compress` 字段透传，不改写）。
5. 连带：`Display Icon` 由"仅 Tile 列"改为"仅 Image 列"（C06）。

**兼容性处理**：遇到含 12/14/15 的文件 → 明确报错 `Map-related column type "Layer" is not supported in this version`，**不静默丢列、不部分加载**（D09）。

### 4.2 多文件多窗口（R2）

**原版**：单窗口单文件；打开新文件即替换；多开只能起两个进程，共享 localStorage，`.lock` 无互斥。

**方案**：单进程多顶层窗口。每个文件一个窗口，各自拥有独立的 `DocumentSession`（数据模型 / 命令栈 / 光标 / 元数据视图），共享应用级配置与剪贴板。

**同文件二次打开**：第二个窗口以**只读模式**打开并顶部提示 `This file is already open in another window (read-only)`；只读窗口禁用保存/编辑入口。

### 4.3 撤销与光标定位（R3）

**根因**：整库反序列化 + 全 UI 重建 → 游标引用失效 → 回退 `(0,0)`。

**方案**：命令模式。每个操作实现 `IUndoableCommand`，包含：

```csharp
interface IUndoableCommand {
    string Description { get; }
    CursorAnchor Before { get; }   // 操作前光标（含 tableId / rowKey / columnId / selection）
    CursorAnchor After  { get; }   // 操作后光标
    void Apply(DocumentSession s);
    void Revert(DocumentSession s);
}
```

**光标定位规则（写入验收标准）**：

1. 撤销 → 恢复到该命令执行**前**的光标；若行列已不存在，回退到最近有效行列。
2. 重做 → 恢复到该命令执行**后**的光标。
3. 删除行 → 优先选中原位置的下一个有效行；若无则上一个；列不变；列不存在则选最近有效列。
4. 插入行 → 光标停在新行。
5. 任何情况下不得无故回到 `(0,0)`。

**锚定方式**：优先用行 ID（有 `TId` 的表）+ 列 ID（元数据中的 columnId）；无 ID 的表用行索引 + 相对偏移。

### 4.4 行复制/剪切/粘贴/插入（R4）

| 动作 | 快捷键 | 语义 |
| --- | --- | --- |
| 复制行 | Ctrl+C（整行选中） | 复制整行所有字段 + 列结构快照 |
| 剪切行 | Ctrl+X | 复制 + 删除（可撤销） |
| 粘贴（覆盖） | Ctrl+V | 覆盖当前行起的 N 行，**保留目标行 ID**（C13） |
| 插入（粘贴插入） | Ctrl+Shift+V | 在当前位置插入 N 行，原数据下移 |

**约束处理**：

- 覆盖时保留目标行 ID（剪贴板里的 ID 被忽略）→ 引用不断。
- 插入时 ID 冲突 → 自动加后缀 `_2`、`_3`；仍冲突则留空并标 `#MISSING`。
- 引用字段原样复制字符串，不做级联。
- 全部操作可撤销，撤销后光标按 §4.3 规则定位。

| 子能力 | 决议 |

| 扩展选择 | Shift 扩展矩形；**不做** Ctrl 不连续区域（C12.2） |

### 4.6 列宽记忆（R6）

1. 存元文件，**绝不进 JSON**。
2. 关联键：`columnId (uuid)`，元数据内维护 `columnId ↔ name` 映射；程序内改名/移动时同步更新；外部改名失配时按列位置回退匹配并修复映射。
3. 持久化时机：拖动结束立即写（节流 300ms）。
4. 默认宽度按类型：Id 140 / Text 240 / Int·Float 90 / Bool 70 / Ref 200 / List 120。
5. 删除列清理配置；重命名/表改名迁移配置。

### 4.7 单元格/行/列背景色（R7）

1. 优先级：**单元格 > 行 > 列 > 默认**。
2. 存元文件，不进 JSON。
3. 行样式键：有 `TId` 用 ID；无 ID 用行索引 + 结构变更时平移（C14）。
4. 列样式键：`columnId`。
5. 单元格样式键：`{rowKey, columnId}`。
6. UI：右键菜单（单元格/行号/列头）→ 预设色板 + 自定义 + 清除。
7. 渲染：半透明叠加，深色背景自动切浅色文字。

### 4.8 元文件（R8）

```jsonc
{
  "metaVersion": 1,
  "fileId": "uuid",
  "tables": {
    "EventCard": {
      "tableId": "uuid",
      "columns": { "col-uuid": { "name": "Title", "width": 240 } },
      "rowStyles": { "vocational": { "bg": "#FFF3CD" } },
      "columnStyles": { "col-uuid": { "bg": "#E7F1FF" } },
      "cellStyles": { "vocational": { "col-uuid": { "bg": "#FFE0E0" } } }
    }
  },
  "windowState": { "width": 1200, "height": 800, "x": 100, "y": 80, "maximized": false }
}
```

| 场景 | 处理 |
| --- | --- |
| meta 不存在 | 首次保存时创建；只读打开不创建 |
| meta 损坏 | 备份为 `.meta.bad`，用默认值继续并提示；不影响主数据 |
| meta 版本更高 | 拒绝写入并提示 |
| meta 版本更低 | 链式升级 |
| 另存为 | 复制 meta 并改写 `fileId` |
| 文件重命名 | 程序内操作时同步重命名 |
| 多窗口同文件 | 单进程内共享同一 `MetaStore` 实例；跨进程用文件锁 + 时间戳比较 |
| 行列增删改 | 按 ID 迁移；无法匹配保留孤儿记录（不立即删） |
| 主文件保存失败 | meta 不写 |

### 4.9 Image 类型改造（R9，新需求）

**原版**：`TImage` 存图片内容的 MD5，图片本体以 base64 存在 `X.img` 里；编辑器通过 MD5 查表渲染。

**新方案**：

| 项 | 原版 | 新方案 |
| --- | --- | --- |
| 存储 | MD5 字符串 | **相对路径字符串**（如 `img/hero.png`） |
| 图片本体 | `X.img`（base64） | 直接引用磁盘文件 |
| 单元格显示 | 通过 MD5 查 dataURL | 直接加载路径，显示缩略图 |
| 编辑 | 选文件 → 算 MD5 | 选文件/拖放 → 存相对路径 |
| 清理 | Clean Images | 不需要 |
| 游戏引擎 | 需解析 `.img` | **直接按路径加载**（这是改造的核心动机） |

**影响**：

- `TFile`（13）保留不变，语义区分：`Image` = 单元格内直接显示缩略图；`File` = 显示文件名 + hover 预览 + open 按钮。
- `Display Icon` 改为对 `Image` 列生效（C06），引用下拉可显示 16px 缩略图。
- **兼容性风险**：若旧文件含 `TImage` 字段（值为 32 位 hex MD5），新软件会把它当作路径 → 显示 `#NOTFOUND`。已确认两个测试文件不含 `TImage`，无实际影响。若将来遇到，提供一次性提示："Detected legacy MD5 image reference, please re-link the file."

### 4.10 HTML5 前端（R10，新需求）

**动机**：原版本身就是 HTML/JS 前端，用 HTML5 可以最大程度复刻其交互手感（尤其是可编辑单元格、内联展开列表、取色器、下拉搜索），且开发迭代快。

**架构方向**：C# 负责数据与文件（唯一的真相源），HTML5 负责渲染与交互，两者通过进程内消息通道通信。具体宿主方案（WebView2 嵌入 vs 本地 HTTP 服务 + 浏览器）在阶段 3 技术方案中给出对比与推荐。

**约束**：

1. 所有数据操作必须经过 C# 服务层，前端不直接读写文件。
2. 表格必须虚拟化渲染（仅绘制可视区），否则万行级会卡。
3. 前端资源随程序分发，不依赖外网。
4. 若前端需要构建步骤，必须提交构建产物，保证"拿到源码即可 `dotnet run`"。

### 4.11 界面外观设置（R11，新需求）

**动机**：原版只有一套浅色皮肤、字号写死。不同人看表格的偏好差别很大——高分屏想小一点、视力不好想大一点、长时间盯着看想换成深色或护眼色。把这些做成设置，比在代码里改常量有用得多。

| 项 | 决议 |
| --- | --- |
| 入口 | View ▸ Settings...（`Ctrl+,`）/ 工具栏的设置按钮 |
| 界面字体大小 | 12–20px，默认 15px，作用于菜单、工具栏、对话框、状态栏 |
| 表格文本大小 | 10–20px，默认 14px，作用于表头、单元格、行号；**行高随字号联动**（`round(字号 × 2.72)`），保证两行文本仍放得下 |
| 配色方案 | 九套：Daylight（浅）/ Midnight（深）/ Graphite（中性灰深）/ Deep Sea（深蓝）/ Sandstone（暖米）/ Blush（粉）/ Lilac（淡紫）/ Olive（橄榄绿）/ Mint（薄荷绿），默认 Daylight |
| 生效方式 | 即时生效（窗口本身就是预览）；Cancel 还原打开前的值，Done 才落盘 |
| 存储位置 | **字号**存浏览器本地存储（`palacedb.settings`），全局生效；**配色**存文件的 `X.cdb.meta.json`（`appearance.scheme`），随文件走。两者都不写进 `.cdb`，都不产生未保存标记 |
| 配色集中管理 | 全部颜色变量集中在 `web/css/themes.css`，加一套配色 = 复制一个 `body[data-scheme="…"]` 块 + 在 `settings.js` 的 `SCHEMES` 里登记 |

### 4.12 保存与备份（C1）

| 项 | 决议 |
| --- | --- |
| 保存方式 | 显式保存（Ctrl+S / 菜单），脏标记显示在标题栏 |
| 自动保存 | **无**，也不提供开关 |
| 自动备份 | 脏状态下每 5 分钟写一次 `X.cdb.bak`，**只保留 1 份**（覆盖） |
| 备份清理 | 保存成功后删除备份 |
| 关闭窗口 | 脏状态时提示 `Save / Don't Save / Cancel` |
| 崩溃恢复 | 启动时若发现 `.bak` 比主文件新 → 提示 `Recover unsaved changes?` |
| 写入方式 | 临时文件 + 原子替换（`File.Replace`），失败不破坏原文件 |

### 4.13 交互细节修订（R12，新需求）

**动机**：R11 之后又跑了一轮实际使用，发现几处"每天都要碰一下"的摩擦：窗口位置会自己跳、侧边栏的两个按钮在两个地方、行号列占得太宽、配色不够挑、id 列删不掉时也不说为什么。

| 项 | 决议 |
| --- | --- |
| 窗口位置 | 记住的位置**只在窗口显示之前**应用一次。窗口一旦上屏，打开任何文件都不再移动它（此前是先显示、再套用记忆位置，看起来像"每次打开文件窗口都跳一下"） |
| id 列 | 可删除，和其它列一样走撤销。唯一的例外是"这张表只剩这一列"——没有列的表无法编辑，此时给出明确提示：先加一列再删 |
| 侧边栏按钮 | 合并为**一个**按钮，固定在工具栏最左侧，展开/收起都是它；尺寸、位置、风格完全一致，只有箭头方向随状态翻转 |
| 侧边栏快捷键 | `Tab` 切换。表格内部 `Tab` 仍是"跳到下一个单元格"，编辑中的 `Tab` 仍是提交，只有焦点不在表格里时才切换侧边栏 |
| 行号列宽度 | 由 52px 收窄到约 28px（`max(24, 字号 × 2)`），够放三位数；更长的行号直接截断，不撑宽列 |
| 配色 | 增加粉色 Blush、淡紫 Lilac、橄榄绿 Olive、薄荷绿 Mint 四套清新配色 |

### 4.14 行高自适应（R13，新需求）

**动机**：单元格里的文本会换行，但行高是固定的，换行后的第二行之后就被裁掉了，
只能靠 tooltip 才看得到全文。写剧情文本、说明文字时这基本没法用。

| 项 | 决议 |
| --- | --- |
| 行为 | 一个值换行后，该行自动长高到能完整显示它，表格里不再有被裁掉的文字 |
| 基准行高 | 不变（仍由字号推导）。只有需要更多空间的行才变高，单行内容的行保持原样 |
| 行号列 | 行号格与行同高，数字垂直居中，不会和内容错位 |
| 与展开面板的关系 | 变高的行会把下面的行、展开的二级表格、滚动条一起推下去，位置保持一致 |
| 上限 | 单个值最多显示约二十行（防一个离谱的值把整张表挤走）；完整文本仍在 tooltip 与编辑器里 |
| 性能 | 只有"变高的行"进入索引，普通表格走的还是原来的等比换算；5000 行实测与改动前同速 |

### 4.15 表格模板（R14，新需求）

**动机**：同一个游戏里经常有"结构一样、数据不同"的几张表（不同章节的事件卡、不同等级的掉落表）。
现在只能建表时手工照抄列定义，之后改了其中一张（比如给 `Des` 改个名字、加一个 `Icon` 列），
其余几张要一张张改，漏一张就出现两套结构。

| 项 | 决议 |
| --- | --- |
| 模板是什么 | 一份**命名的列定义清单**（名称、类型、必填、默认值、显示格式、Enum/Flags 取值、List 字段）。跟着同一个模板走的表，这些设置保持一致 |
| 存放位置 | 存在 `X.cdb.meta.json`（`metaVersion` 2 的 `templates`）。它是编辑器用来对齐几张表的约定，游戏端读数据不需要它，所以**不写进 `.cdb`** |
| 创建 | 表右键 ▸ Table Settings ▸ Save these columns as a new template...；新建表时也可以直接选一个模板 |
| 修改同步 | 在任一成员表里改列（改名 / 改类型 / 加列 / 删列 / 调顺序 / 改列选项）→ **镜像到所有成员表**，整体一步撤销 |
| 破坏性操作 | 删除列、或换成数据不兼容的类型，若别的表里还有值 → **二次确认**，列出每张表受影响的行数与总共会丢失的值数 |
| 套用检查 | 缺列、顺序不同 → 允许（缺的列补空，顺序按模板重排）；多出模板没有的列、同名列类型/字段不一致 → 拒绝并报告，**什么都不改** |
| 多出列的那一种冲突 | 额外给一个「把这些列加进模板」的捷径（用户选择：给），避免只能手工删列 |
| 新列默认值 | 通过模板补进来的列**不给已有行写默认值**（用户选择：不写），保持"没有就是没有" |
| 界面提示 | 侧栏用小圆点标记跟随模板的表，**不显示模板名**，鼠标悬停才在 tooltip 里说明（用户选择）；状态栏显示 `Template: 名称` |

## 5. 需求确认结果（Q1–Q16）

> 以下为最终决议。"决策依据"保留原始分析，便于日后回溯。

### Q1 保存模型 → **C（显式保存），无自动保存开关，增加 5 分钟自动备份**

- 显式保存 + 脏标记 + 关闭提示。
- 脏状态下每 5 分钟写 `X.cdb.bak`，只保留 1 份。
- **依据**：需求 2 要求"关闭未保存提示"，与原版"每次改动即写盘"根本冲突；显式保存是唯一自洽方案。

### Q2 撤销模型 → **B（命令模式）**

- 每个操作带逆操作 + 前后光标快照。
- **依据**：R3 要求"光标与操作历史关联"，快照模型天然做不到；且命令模式内存占用低。

### Q3 地图数据类型 → **全部删除**（已用测试文件验证不受影响）

- 删除 12/14/15 三类 + `props.level` + 压缩 + 重映射。
- 遇旧文件含这些类型 → 明确报错，不部分加载。

### Q4 LZ4 压缩开关 → **删除**

- `compress` 字段原样透传，不改写、不提供 UI。

### Q5 Image 存储 → **改为路径字符串（新需求 R9）**

- 取消 MD5 与 `.img`；单元格内可视化；`Display Icon` 改挂 Image 列。

### Q6 git 冲突合并 → **A（保留）**

- 检测 `.mine`，能合并则合并，否则拒绝加载并提示。

### Q7 JqPages → **A（删除）**

- 不再监听 6669 端口。

### Q8 分隔线写盘 → **A（整数数组）**

- 与现有文件一致，1.5 与新版均可读；解析兼容整数 / `{index}` / `{id}` 三种。

### Q9 文本单元格 → **A（多行文本框，自动增高）**

- Enter 换行，Ctrl+Enter 或失焦提交。

### Q10 多窗口 → **A（单进程多顶层窗口）**

- 每文件独立 `DocumentSession`。

### Q11 同文件二次打开 → **B（只读 + 提示）**

- 第二个窗口只读，顶部提示原因。

### Q12 多单元格编辑

| 子项 | 决议 |
| --- | --- |

| 12.2 Ctrl 追加不连续区域 | **不做** |
| 12.3 批量输入 | 键入改活动格；Ctrl+Enter 填满选区 |

### Q13 行粘贴 ID 策略 → **A（覆盖保留目标 ID）；插入冲突自动加后缀**

### Q14 无 ID 表的行样式键 → **A（行索引 + 结构变更时平移）**

### Q15 界面语言 → **英文界面；代码、标识符、注释全部英文**

- 包括 UI 文案、变量/类/方法命名、XML 注释、提交信息。
